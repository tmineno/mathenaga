# ADR-002: 用語の定義は、ビルド時に作る定義索引を閲覧時に一括で取得して表示する

## Context

章ページの本文の用語に触れると、ポップアップに定義を出す([site.md](../spec/site.md) の P-01)。定義はほかの章にあることが多い。定義の本文は定義元の1か所にだけ書き、ほかの章に複製しない。サイトは静的ファイルだけで動き、サーバー側の処理を持たない。

## Decision

- ビルド時に、全定義を1つの JSON(`defs.json`)にまとめる。各項目は、描画済みの HTML(数式と式番号を含む)と、名前・英語名・定義の番号・別名・駅・表示番号・章・定義元の URL を持つ(形式は [build.md](../spec/build.md))。
- 閲覧時は、最初にポップアップを開くときに `defs.json` を一括で取得し、以後は取得し直さない。

## Consequences

- 取得は1ページにつき1回で済み、どの章からも同じ形で定義を引ける。
- 定義の本文は定義元の1か所にだけあり、ページと `defs.json` は同じビルドから作るので、食い違わない。
- 章が増えると `defs.json` が大きくなり、最初のポップアップを開くまでの待ち時間が延びる。
- 定義の本文の中の `[[…]]` は、ポップアップの中ではボタンやリンクにしない(ポップアップの中からさらにポップアップを開かない)。

## Alternatives

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 定義索引を取得(採用) | ビルド時に全定義の索引ファイルを作り、閲覧時に取得する | 取得が1回で済む。どの章からも同じ形で引ける | 章が増えると索引が大きくなる |
| 定義ごとの断片を取得 | ビルド時に定義ごとの小さなファイルを作り、触れた用語の分だけ取得する | 必要な分だけ読む | ファイル数が増える |
| 定義元ページから抽出 | 閲覧時に定義元の章ページを取得し、定義ブロックを取り出す | ビルド時の追加生成がない | 章ページ全体を読むので重い。ページ構造の変更に弱い |
| 各ページに定義を埋め込む | ビルド時に、そのページで使う定義を HTML に入れておく | 取得が要らない | 定義の本文がページごとに複製される |

## Exit criteria

`defs.json` の大きさが、最初のポップアップの待ち時間として目に見える問題になったら見直す。数値は、そのときに測って判断する。移る先の第一候補は「定義ごとの断片を取得」である。
