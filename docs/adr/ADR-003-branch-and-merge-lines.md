# ADR-003: 支線が、前の支線から分かれることと、複数の路線から合流することを許す

> 途中の駅の前提を乗換駅の印で示す部分は、[ADR-006](ADR-006-chapter-cards-and-prerequisite-arrows.md) で前提の矢印に置き換えた。分岐と合流の規則はこの ADR のまま使う。

## Context

路線図の支線は、これまで幹線からしか分かれられなかった([route-map.md](../spec/route-map.md) の Non-goals)。前提が支線の上にある内容を新しい路線にできないので、新しい章は既存の支線の末尾に、章番号の順で足すしかなかった。たとえば変分法の章はノルム空間(解析線)だけを前提にするが、解析線の末尾に置くと、関係のないスペクトル理論の後ろに並ぶ。また、解析と位相が交わる内容(測地線は変分法と多様体の両方を前提にする)は、どちらか一方の路線にしか載せられず、もう一方の前提は乗換駅の印でしか示せなかった。

## Decision

- 支線は、幹線か、路線ファイルでそれより前にある支線から分かれられる。分岐駅は支線の最初の駅の requires から決め、1つ以上ある。2つ以上あれば、支線はそれらの路線から合流し、図にループができる。決め方と配置は [route-map.md](../spec/route-map.md) の「分岐駅」「配置」に書く。
- ほかの路線と線でつなぐのは、支線の最初の駅だけにする。途中の駅の前提は、これまでどおり乗換駅の印で示す。
- 上の段と下の段の両方の路線から合流する支線は、幹線と同じ高さで右に置く。
- 支線の木の深さに上限を置かない。
- 線どうしの交差は許し、札・駅名・印・章の札と線が重ならないことだけを保証する。

## Consequences

- 内容のまとまりごとに路線を作れる。路線の並びが前提の関係と食い違わなくなる。
- requires は循環しない(E06)うえに、親の路線は路線ファイルで前にある路線に限るので、支線の親子も循環しない。
- 今の基準原稿では、どの支線も最初の駅が幹線の駅だけを前提にしているので、図は変わらない。
- 受け入れテスト 10(hilbert-space だけを前提にする新しい路線は E12)の意図が逆になり、正しい路線として描くことを確かめるテストに変わる。
- 図が縦にも長くなり、線の交差が増える。重なりは座標の単体テスト(受け入れテスト 6)で防ぐ。
- 乗換案内は、分岐駅が2つ以上ある支線にも対応する([build.md](../spec/build.md)、[site.md](../spec/site.md))。

## Alternatives

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 分岐と合流を許す(採用) | 支線が前の支線から分かれ、複数の路線から合流できる | 前提の関係を路線の形で示せる | 配置の規則が増え、交差が増える |
| 分岐だけを許す | 親の路線を1つに限り、2つ目以降の前提は乗換駅の印で示す | 配置が木になり、交差が少ない | 解析と位相が交わる内容を図で示せない |
| 乗換の札だけ足す | 路線は幹線から分け、最初の駅の横に「A06 から乗換」のような札を付ける | 配置を変えずに済む | 路線の形が前提を表さない |
| 既存の支線の末尾に載せる(従来) | 新しい章を既存の路線に、章番号の順で足す | ツールを変えない | 路線の並びが前提の関係と食い違う |

## Exit criteria

合流する支線が増えて、交差で図が読めなくなったら見直す。そのときは、交差を減らす配置(親の路線の段を入れ替える、合流する支線を幹線の高さに複数置く)を検討する。
