# ADR-005: 注・補足・参考文献を足し、文献は検索 API で実在を確かめてから使う

## Context

- 原稿の地の文に、話の筋から外れた補足が混ざっている。第0章だけで、ほかの本の書き方に触れる文(「〜と書く本もあります」「本によって違います」)が5か所ある(2026-11-03 の grep)。読み飛ばしてよい補足を表すブロックはない。pitfall は、読者が間違えやすい点を書く場所である。
- 原稿は文献を1つも引いていない。証明を省いた定理や、分野の応用で述べた事実の根拠を、読者がたどれない。
- 原稿は AI も書く。AGENTS.md §8 は出典のでっち上げを禁じているが、規則を書いただけでは、実在しない文献や、別の文献の識別子が混ざるのを止められない。
- 2026-11-03 に、文献の検索 API を試した。

| 試したこと | 結果 |
|---|---|
| CrossRef に実在の DOI(`10.1038/nature14539`) | 書名・著者・年が返る |
| CrossRef に架空の DOI(`10.1038/nature99999999`) | 404 |
| CrossRef で Kreyszig『Introductory Functional Analysis with Applications』を書誌で検索 | 上位3件は、どれもこの本の書評の DOI(種類は journal-article)。本の DOI はない |
| OpenLibrary に架空の ISBN(978-0-00-000000-2) | 無関係な本の記録へ転送され、200 が返る(ISBN-10 に 0000000000 と登録された記録) |
| NDL サーチに架空の ISBN(978-4-00-000000-0) | 3件当たる。どれも ISBN を誤記した本の記録で、型は `dcndl:ErrorISBN` |
| NDL サーチで杉浦光夫『解析入門』 | 東京大学出版会の版が、ISBN つきで返る |

識別子で記録が見つかることは、文献が実在することの確認にならない。返ってきた記録の書名・著者・年・種類を、引こうとする文献と照らし合わせる必要がある。また、教科書の多く、とくに和書には DOI がない。

## Decision

- **注**:文の中に `^[注の本文]` と書く。印「注N」を置き、押すか重ねるとポップアップで本文を出す。本文は、注を書いた駅か節の末尾にも一覧で出す。番号は章ごとに振る。
- **補足**:段落単位の、読み飛ばしてよい補足は `::: remark` に書く。札は「補足」。
- **参考文献**:文献は `content/references.yml` に1か所で書く。本文では `[[@文献ID]]` で引き、「[N]」と表示する。番号は章ごとに、初めて引いた順に振る。章末(確認問題の後、この先の前)に、その章で引いた文献を並べる。番号に重ねると、ポップアップに書誌を出す。
- **定義の本文には、注も文献の引用も書けない**。定義はポップアップと定義索引で、ほかの章のページにも出るためである。
- **実在の確認**:
  - `npm run refs:verify` が、DOI は CrossRef、ISBN は NDL サーチ(なければ OpenLibrary)に問い合わせる。返った記録の書名・第1著者・年・種類が一覧の項目と一致したときだけ、確認の記録(`content/references.verified.json`)を書く。
  - ビルドはネットワークを使わず、確認の記録がない文献と、記録を取った後に書き換えた文献があれば止まる。
  - CI は、文献の一覧か確認の記録を変えた PR で確認をやり直す。手で書いた記録はここで見つかる。
  - AI も文献を足せる。ただし `refs:verify` を通したものだけで、書誌は検索 API とは別の情報源から書く。

## Consequences

- 新しい記法(`^[…]`、`remark`、文献を指す `[[@ID]]`)をツールに足す。ADR-004 により、使う例をツールの変更と同じコミットでテスト用原稿に足す。
- 確認できるのは「その識別子の文献が実在し、書誌が一覧の記載と一致する」ことまでである。引いた箇所に、その内容が書いてあるかは確かめられない。そこは執筆の規則(AGENTS.md)と、PR での人間の確認で担う。
- 書誌を検索 API の記録から書き写すと、照合は記録をそれ自身と比べることになり、意味を失う。書評の DOI を本に付けるような、別の実在の記録を選んだ誤りも通ってしまう。そのため、書誌は API とは別の情報源から書く規則にする。
- 確認は外部の API に依存する。API が止まると、文献を変えた PR の CI は通らない。ビルドと、文献を変えない PR の CI は影響を受けない。
- ウェブページは文献にできない。実在と書誌を確かめる手段がないためである。
- 確認の記録はリポジトリに入る。照合した記録の書誌を残すので、後から確認の根拠をたどれる。
- 位置情報つきのコピー(site.md の P-08)の区画に「参考文献」が加わる。注の印は、選んだ文に含めない。
- アンカーの指す要素が折りたたみの中にあれば開く、という規則を、応用だけでなくすべての折りたたみに広げる。証明の詳細や答えの中の注の印へ、一覧から戻れるようにするためである。

## Alternatives

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 文中の注と補足のブロックを両方足す(採用) | 1〜2文の補足は注、段落になる補足はブロック | 補足の長さに合った置き方ができる | 書き分けの規則が要る(AGENTS.md に書く) |
| 注を章末にまとめる | 本の脚注・後注と同じ形 | 見慣れた形 | 1章が1ページで長く、注が本文から離れすぎる |
| 傍注(右の余白) | 注を本文の横に置く | 本文から目を離さずに読める | 置けるのは 1340px 以上の幅だけで、しおり・起票のアイコンと場所が重なる |
| ラベル式の脚注(`[^1]` と、別の行の `[^1]: …`) | Markdown で広く使われる形 | 長い注も書ける | 本文と注が離れる。ラベルの書き忘れや、使われないラベルの検査が要る |
| markdown-it-footnote を使う | 既存のプラグイン | 作る量が少ない | 番号の振り方、駅や節の末尾への移動、位置つきコピーをツールの規則で決められない。記法をコアで読む方針(ADR-001)と合わない |
| 引用を Pandoc の `[@key]` で書く | 学術文書で広く使われる形 | 見慣れた形 | 今の `[[@ID]]` と1文字違いで紛らわしい |
| 引用を著者と年で表示する(Rudin 1976) | 本文だけで本の見当がつく | 番号の一覧を見なくてよい | 和書と洋書、共著、同じ著者で同じ年の本の書き分けの規則が要る |
| サイト全体の文献ページ | 全文献を1ページに並べる | 一覧できる | ページが1種類増え、章で引いた文献から離れる。今回は作らない |
| DOI だけで確かめる | CrossRef で引けるものだけ認める | 確認が最も確か | 和書と、DOI のない教科書を引けない |
| 識別子が見つかるかだけで確かめる | 404 でなければよしとする | 作る量が少ない | 架空の ISBN でも無関係な記録が当たる(Context) |
| 確認をビルドの中で行う | ビルドが毎回問い合わせる | 仕組みが1か所にまとまる | ビルドがネットワークに依存し、同じ原稿から同じ `dist/` ができる保証が崩れる |
| 文献を足すのを人間だけにする | AI は既存の文献を引くだけ | 人の目を必ず通る | 人間の手間が増える。人間が選んだ方式ではない |

## Exit criteria

次のどれかが起きたら見直す。

- 確認に使う API(CrossRef、NDL サーチ、OpenLibrary)のどれかが使えなくなった、または応答の形が変わった。
- 文献を変えた PR の CI が、API の不調で落ちることが続いた。
- 確認の記録のある文献で、引いた箇所の内容の誤りが見つかった(書誌の照合だけでは足りないことを示す)。
