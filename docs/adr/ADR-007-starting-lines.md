# ADR-007: 支線を、ほかの路線から分けずに始発の路線として描けるようにする

## Context

路線図では、幹線以外の路線はすべて支線で、幹線か前の支線の駅(分岐駅)から路線の色の線を引いて分けてきた([ADR-003](ADR-003-branch-and-merge-lines.md)、[route-map.md](../spec/route-map.md))。路線をまたぐ前提のうち線で届かないものは、章の札どうしの矢印で示す([ADR-006](ADR-006-chapter-cards-and-prerequisite-arrows.md))。

微積分の章(微分、測度と積分、多変数の微分)を足す路線を検討したとき、次の問題があった。

- 新しい支線として分けると、支線が増えて路線図が読みにくくなる。今の原稿では、支線はすでに4本(測度線・解析線・幾何線・集合線)ある。
- 解析線に入れて測度線もまとめると、支線は3本になるが、解析線が11章の1本の線になり、全体の図が横に長くなる(試算で 2904×767px)。
- 微積分の章の前提は、開集合・連続写像(本線)と完備性(解析線)にまたがり、どれか1つの駅から分かれる形が内容に合わない。

路線は、ほかの路線から分かれる形でなくても、自分の最初の章から始めてよい。始発を1つにしておく必要はない。

## Decision

- 路線ファイルで `start: true` を書いた支線を、始発の路線とする。始発の路線は分岐駅を持たず、分岐の線を引かない。最初の駅の前提は、ほかの路線をまたぐ前提と同じ規則で、前提の矢印として描く。
- 始発の路線の段は layout(`up` か `down`)で決め、支線と同じく路線ファイルの順に幹線から遠い段へ置く。最初の章は、最初の駅が前提にする章のうち最も右の章の、次の列に置く。前提がなければ左端の列に置く。こうすると左から右へ読む順が保たれ、最初の駅への前提の矢印は右向きになる。
- 始発の路線の最初の駅は、幹線か、路線ファイルで前にある路線の駅だけを前提にできる(後ろの路線を指せば E12)。後ろの支線は、始発の路線から分かれてよい。
- 始発の路線は、章ページの「ほかの路線への案内」に出さない(分岐駅がない)。

## Consequences

- 支線を増やさずに、新しい路線を足せる。微積分の路線は、測度線の3章とあわせて1本の始発の路線にし、支線は解析線・幾何線・集合線の3本になる。
- 始発の路線とほかの路線のつながりは、路線の色の線ではなく細い前提の矢印で示されるので、目立たない。前提が2つ以上の路線にまたがる場合は、矢印が増える。
- 始発の路線は「ほかの路線への案内」に出ないので、章ページからの入口は、路線図と、始発の路線の最初の章のページの「前提」になる。
- 路線ファイルの検査(`start` の値と layout の組み合わせ)、分岐駅の判定、段と列の決め方、E12 の検査を変える。

## Alternatives

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 始発の路線(採用) | 分岐の線を引かず、前提を矢印で示す | 支線を増やさない。前提が複数の路線にまたがっても形が素直 | つながりが細い矢印だけになる。仕様と実装の変更が要る |
| 新しい支線にする | 微積分の路線を、連続写像などから分かれる支線にする | 今のツールのまま描ける | 支線が5本になる。分岐駅を1つに決めると、内容に合わない前提を書くことになる |
| 解析線にまとめる | 微積分と測度線の章を解析線に入れる | 支線が3本になり、読む順が一本道になる | 解析線が11章になり、全体の図が横に長くなる |
| 左端から始める | 始発の路線の最初の章を、いつも左端の列に置く | 始発が並んで見える | 前提の矢印が右から左へ戻る向きになり、読む順と逆になる |

## Exit criteria

始発の路線へ進む読者が入口を見つけにくい(章ページの案内がないため)ことが分かったら、始発の路線の最初の駅の前提を含む章の案内に、始発の路線を足すことを検討する。
