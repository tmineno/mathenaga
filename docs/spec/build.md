# Feature: オーサリングツール(ビルド)

> **Status:** Draft · Spec-driven kickoff · 2026-11-01
> **Owner:** Taiki Mineno
> **Related:** [content-format.md](content-format.md)、[route-map.md](route-map.md)、[site.md](site.md)、[reference-check.md](reference-check.md)、[ADR-001](../adr/ADR-001-handmade-build-tool.md)、[ADR-002](../adr/ADR-002-definition-index.md)、[ADR-005](../adr/ADR-005-notes-and-references.md)

## Goal

`npm run build` を1回実行すると、`content/` の原稿から、章ページ・分野の入口ページ・トップページ・路線図・定義索引がそろったサイト全体が `dist/` にできる。原稿に誤りがあれば一覧を出して止まり、`dist/` には手を付けない。同じ原稿からは、いつもバイト単位で同じ `dist/` ができる。

## Non-goals

- 差分ビルド。毎回サイト全体を作り直す。表示番号・名前の解決・乗換駅など、章をまたぐ値が古いまま残らないようにするため。
- フレームワーク(Eleventy、Astro など)の利用([ADR-001](../adr/ADR-001-handmade-build-tool.md))。
- サイト内検索(P-06)。公開が済んでから、ビルドの後段に足すかを検討する。
- GitHub Pages 以外への公開の自動化。出力はどの静的ホスティングにも置ける形にするが、公開の手順は GitHub Pages の分だけ用意する。

## Inputs / Outputs

### 入力

- `content/` の原稿([content-format.md](content-format.md))。文献の一覧(`references.yml`)と確認の記録(`references.verified.json`)を含む。ビルドは確認の記録を読むだけで、問い合わせはしない([reference-check.md](reference-check.md))。
- 環境変数 `MATHENAGA_BASE_PATH`:ベースパス。既定は `/`。`/` で始まり `/` で終わる。
- 環境変数 `MATHENAGA_REPO_URL`:改善案を起票する GitHub のリポジトリの URL(`https://github.com/<owner>/<repo>`)。任意。渡せば章ページの各駅に起票のアイコンを出し、本文を選んだときの選択メニューに「起票」と「編集」を出す([site.md](site.md) の P-07・P-12)。そのために、章ページの段落ごとに、原稿のファイルの中の行の範囲を書き込む。全ページの上端のバーには、リポジトリへのリンクを出す(P-13)。

### ビルドの流れ

1. **1段目(グラフ)**:全ファイルを読み、章グラフを作り、下の値をすべて導いて検査する。HTML はまだ作らない。数式が KaTeX で解釈できるかもここで確かめる。
2. **2段目(ページ)**:章ページ・分野の入口ページ・トップページ・路線図・定義索引を作り、`dist/` に書く。

- 1段目でエラーが1つでもあれば、2段目に進まず、`dist/` を書き換えない。
- 2段目は `dist/` を消してから書き直す。消した章のページなど、前回の出力は残さない。

### 章グラフ

章グラフは、路線・分野・章・駅・定義・定理と、その間の関係(章の路線、駅を含む章、駅の requires、定義と定理を含む駅、分野の目標)からなる。

### 導出する値

執筆者に書かせずに、ツールが次の値を導く。

| 値 | 導き方 |
|---|---|
| 読む順 | 駅を、章番号の順、章の中では見出しの順に並べる |
| 駅の表示番号 | 路線記号に、路線の中での読む順の通し番号を付ける。番号は 01 から、2桁に満たなければゼロで埋める(A01) |
| 章の表示番号 | 「第N章」(N は章番号) |
| 式番号 | 別行立ての式ごとに「(章番号.通し番号)」。通し番号は章ごとに 1 から、章ページに並ぶ順([site.md](site.md) の「章ページの構成」と「駅の表示」)に振る。この順は原稿に書いた順と違うことがある(application を駅の末尾に移す、分野版を分野の並びに並べ直す、ふりかえりを確認問題より前に置く、など)。折りたたむ式(証明の詳細、答え、分野版)にも振り、分野の選択では変わらない |
| 定義と定理の番号 | 定義(definition)と定理(theorem)ごとに「章番号.通し番号」(3.2)。通し番号は章ごとに 1 から、定義と定理をまとめて原稿に書いた順に振る。式番号とは別に数え、分野の選択では変わらない |
| 図番号 | 図(画像だけの段落、[content-format.md](content-format.md)「図」)ごとに「図 章番号.通し番号」。通し番号は章ごとに 1 から、章ページに並ぶ順に振る(式番号と同じ順。式番号とは別に数える)。分野の選択では変わらない |
| 応用番号 | application ごとに「応用 章番号.通し番号」。通し番号は章ごとに 1 から、全分野をまとめて章ページに並ぶ順(駅の順 → 分野の並び → 書いた順)に振る。分野の選択では変わらない。定義・定理・式・図とは別に数える |
| 注番号 | 注(`^[…]`)ごとに「注N」。N は章ごとに 1 から、注の印が章ページに並ぶ順(式番号と同じ順)に振る。分野の選択では変わらない。ほかの番号とは別に数える |
| 文献番号 | 章で引いた文献ごとに「[N]」。N は章ごとに 1 から、その文献を章で初めて引いた位置が章ページに並ぶ順(式番号と同じ順)に振る。同じ文献は、章の中では何度引いても同じ番号になる。注の本文の中の引用は、その注の印の位置にあるものとして数える。章が違えば、同じ文献でも別に数える |
| 章の参考文献 | 章で引いた文献を、文献番号の順に並べたもの |
| 乗換駅 | 別の路線の駅の requires に含まれる駅 |
| 分野の範囲 | 分野の目標駅と、そこから requires をさかのぼって集めた駅 |
| 分野内の章の順序 | 分野の範囲の駅を1つでも含む章を、章番号の順に並べたもの |
| 範囲外の駅 | 分野を選んだとき、章の駅のうち分野の範囲に入らないもの |
| 範囲外の章 | 分野を選んだとき、分野の範囲の駅を1つも含まない章 |
| 章の前提 | 章の駅の requires が指す駅を含む、ほかの章(章番号の順)。直接の前提だけで、さかのぼらない |
| 次の章 | 下の規則 |
| 乗換案内 | 下の規則 |
| 分岐駅 | [route-map.md](route-map.md) の規則 |

**次の章**:章 C の次の章は、選んだ分野 F によって次のように決まる。

| 状態 | 次の章 |
|---|---|
| F を選んでいて、C が F の章の順序に入る | F の章の順序で C の次にある章。なければなし(終着) |
| F を選んでいて、C が範囲外の章 | F の章の順序のうち、章番号が C より大きい最初の章。なければなし |
| 分野を選んでいない | 全章を章番号の順に並べたとき、C の次にある章。なければなし |

**乗換案内**:分野 F を選んだ章 C には、次の条件をみたす支線 L ごとに1項目を作る。分野を選んでいないときは作らない。

- L は C の路線と異なる。
- L に、F の範囲に入る駅がある。

各項目は、L の名前、F の路線図での L の分岐駅(1つ以上。読む順に並べる)とそれぞれを含む章、F の範囲に入る L の最初の駅とそれを含む章を持つ。分岐駅ごとに、それが C にあるかどうかも持つ。項目の並びは路線ファイルの順にする。

### 定義索引(defs.json)

全定義を1つの JSON にまとめる([ADR-002](../adr/ADR-002-definition-index.md))。キーは定義の ID で、ID の文字コード順に並べる。各項目は次の値を持つ。

| キー | 値 |
|---|---|
| name | 定義の name |
| en | 定義の en |
| number | 定義の番号(「導出する値」の定義と定理の番号。「3.1」の形) |
| aliases | 別名の配列(なければ空) |
| station | 定義を含む駅の ID |
| code | その駅の表示番号 |
| stationName | その駅の駅名 |
| chapter | 定義を含む章の章番号 |
| chapterTitle | その章のタイトル |
| url | 定義の場所。`<ベースパス>chapters/<章ID>/#def-<定義ID>` |
| html | 定義の本文を描画した HTML。数式は KaTeX で描画済みで、別行立ての式には章ページと同じ式番号を付ける。`[[…]]` はボタンやリンクにせず表示する文字だけに、`[[@…]]` は表示番号の文字だけにする |

### 出力(dist/)

```text
dist/
  index.html                        トップページ
  fields/<分野ID>/index.html         分野の入口ページ
  chapters/<章ID>/index.html         章ページ
  chapters/<章ID>/figures/…          図(原稿の figures/ をそのままコピーする)
  defs.json                         定義索引
  assets/                           CSS、閲覧時のスクリプト、favicon、KaTeX の CSS とフォント
```

- ページの中のリンク、CSS・スクリプト・図の参照、`defs.json` の読み込みは、ベースパスを付けて書く(ベースパスが `/mathenaga/` なら `/mathenaga/chapters/…`)。
- ページが読み込むファイル(CSS・スクリプト・favicon・KaTeX の CSS・図)と `defs.json` の URL には、版の印 `?v=〈中身の SHA-256 の16進の先頭 10 文字〉` を付ける。公開の配信はファイルをしばらくブラウザに残させる(GitHub Pages は 10 分)ので、公開した直後に、新しいページが残っていた古い CSS・スクリプト・定義索引と組み合わさらないようにするためである。`defs.json` の URL は、ページの `<html>` の `data-defs` 属性で閲覧時のスクリプトに渡す。KaTeX のフォントには付けない(KaTeX の版を上げない限り変わらない)。
- 路線図の SVG は、使うページの HTML に埋め込み、別のファイルにはしない。
- KaTeX の CSS とフォントは `dist/` にコピーして配信し、CDN を使わない。フォントは woff2 だけにする。
- 生成物には、ビルドの日時など、原稿以外の理由で変わる値を入れない。

### 公開する入口(コマンドと設定)

| 入口 | 事前条件 | 事後条件 | 失敗したとき | 副作用 |
|---|---|---|---|---|
| `npm run build` | Node.js 22 以上。依存をインストール済み | 終了コード 0。`dist/` にサイト全体があり、通知を標準出力に出す | エラーの一覧を標準エラー出力に出し、終了コード 1。`dist/` は変えない | `dist/` を消して書き直す |
| `npm run dev` | `npm run build` と同じ | `127.0.0.1` で `dist/` をベースパスの下に配信する(ポートの既定は 8000、環境変数 `PORT` で変える)。`content/` と `src/` の変更のたびに全体を作り直し、開いているブラウザを再読み込みする | ビルドのエラーは端末に出し、ブラウザは前回成功した出力のまま。サーバーは止めない | `dist/` を書き換える |
| `npm test` | 依存と、Playwright が使うブラウザをインストール済み | 単体テスト、テスト用原稿を使った結合テスト、Playwright でブラウザを動かす閲覧テスト([site.md](site.md))を実行し、すべて通れば終了コード 0 | 失敗したテストを出し、終了コードは 0 以外 | テストの出力は一時ディレクトリに書き、`dist/` には触れない |
| `npm run refs:verify` | ネットワークにつながる | 文献の実在を検索 API で確かめ、確認の記録を書く([reference-check.md](reference-check.md)) | 同左 | `content/references.verified.json` を書き換える |
| `MATHENAGA_BASE_PATH` | `/` で始まり `/` で終わる | すべてのリンクと読み込みに付く | 形式が違えば E13 で止まる | なし |
| `MATHENAGA_REPO_URL` | 空か、`https://github.com/<owner>/<repo>` の形 | 空でなければ、章ページの各駅に、そのリポジトリの Issue 作成画面へのリンクを置く。段落ごとに原稿の行の範囲を書き込み、選択メニューから Issue 作成画面と原稿の行を開けるようにする。全ページの上端のバーに、リポジトリへのリンクを置く | 形式が違えば E13 で止まる | なし |

### CI と公開

- CI(GitHub Actions)は format → lint → typecheck → test の順に実行し、どれかが失敗したらマージできないようにする。型は JSDoc で書き、typecheck で検査する。使う道具は CI を作るときに決め、バージョンを固定する。
- CI の test では閲覧テストも実行する。そのためにブラウザをインストールする手順を CI に入れる。
- 文献の一覧(`references.yml`)か確認の記録(`references.verified.json`)を変えた PR では、今の原稿とテスト用原稿のそれぞれについて、変えた側に `npm run refs:verify -- --check --content <原稿の場所>` も実行し、失敗したらマージできないようにする。CI でネットワークを使うのはこの手順だけで、ほかの PR では実行しない([reference-check.md](reference-check.md))。
- 公開は、main への push で `npm run build` を実行し、`dist/` を GitHub Pages のプロジェクトサイトに置く。ベースパスは `/<リポジトリ名>/` で、公開のワークフローがリポジトリ名から作って `MATHENAGA_BASE_PATH` に渡す。リポジトリの URL も `MATHENAGA_REPO_URL` に渡し、改善案の起票のアイコンとリポジトリへのリンクを出す。手元のビルドとプレビューの既定は、ベースパスが `/`、`MATHENAGA_REPO_URL` は空(アイコンとリンクなし)のまま。

## Failure modes

| きっかけ | 検出 | 外から見える振る舞い | 直し方 |
|---|---|---|---|
| 原稿の誤り | 1段目の検査([content-format.md](content-format.md) の E01〜E11・E14・E15、[route-map.md](route-map.md) の E12) | エラーの一覧、終了コード 1、`dist/` は変わらない | 原稿を直して再実行する |
| 文献を足した・書き換えたが、実在を確かめていない | 1段目の検査(E15) | 同上 | `npm run refs:verify` を実行し、確認の記録をコミットする |
| `MATHENAGA_BASE_PATH` の形式が違う(`mathenaga` など) | 1段目の前の設定の読み取り(E13) | 同上 | 値を直す |
| `MATHENAGA_REPO_URL` の形式が違う(`github.com/example/mathenaga` など) | 1段目の前の設定の読み取り(E13) | 同上 | 値を直すか、空にする |
| 依存がインストールされていない | Node のモジュール解決 | Node のエラーで止まり、終了コードは 0 以外 | `npm ci` を実行する |
| Playwright が使うブラウザがインストールされていない | `npm test` の閲覧テストの起動 | 閲覧テストが失敗し、ブラウザがないことを出す | Playwright のブラウザをインストールする |
| ロゴのドットマップ(`src/site/assets/logo.txt`)の形式が違う | 2段目のページの生成([site.md](site.md)「ロゴと favicon」) | ファイル名と行番号を出し、終了コード 1。`dist/` は変わらない | ドットマップを直す |
| `dist/` を消せない・書けない | 2段目のファイル操作 | 原因のパスを出し、終了コード 1。`dist/` が途中までになることがある | 権限を直して再実行する |
| `npm run dev` が書きかけのファイルを読む | 1段目の検査 | エラーを端末に出し、次の保存で作り直す | 保存し直す |
| ベースパスの付け忘れ(忘れやすい) | 受け入れテスト 14 | ベースパスが `/` のときは気づけず、`/リポジトリ名/` の下に置くとリンクが切れる | リンクを作る関数を1つにまとめ、テストで確かめる |
| 消した章のページが残る(忘れやすい) | 受け入れテスト 15 | 存在しない章へのリンクが生きて見える | `dist/` を毎回消して作り直す |

## Performance / Safety

- 再現性:同じ原稿と同じベースパスからは、バイト単位で同じ `dist/` ができる。
- 速度:`npm run dev` は、原稿を保存してからブラウザの表示が変わるまでを 5 秒以内にする。テスト用原稿で測った値は 0.5 秒前後である(2026-11-01、2 回の実行で 470 ms と 508 ms)。`npm run build` には制約を置かない。
- ビルドとテストはネットワークを使わない。文献の実在の確認は `npm run refs:verify` が別に行い、ビルドはその記録を読むだけにする([ADR-005](../adr/ADR-005-notes-and-references.md))。
- 削除するのはリポジトリの `dist/` だけで、出力先は設定で変えられない。
- `npm run dev` のサーバーは `127.0.0.1` だけで待ち受ける。
- 依存のバージョンは完全に固定し(`^` と `~` を付けない)、lock ファイルをコミットする。

## Acceptance tests

テスト用原稿を入力にした結合テストで確かめる([ADR-004](../adr/ADR-004-frozen-test-manuscript.md))。数式と式番号の個数、定義の ID の一覧は期待値を手で書かず、テストがビルドとは別の数え方で原稿から数える。

次のことは、値を書かない形で今の原稿でも確かめる。期待する個数や並びは、テストが原稿から作る:8 のうち全章の参照が解決することと数式の個数、9 のうち `defs.json` に全定義が1項目ずつ ID の順に並ぶこと、11 のうち式番号の振り方、16、21、26 のうち版の印がファイルの中身のハッシュと一致すること、27 のうち応用の札の番号。

1. 表示番号:reading-symbols = Z01、sets-maps = Z03、metric-space = M02、continuous-map = M04、cauchy-sequence = A01、banach = A04、picard-lindelof = A05、hilbert-space = A08、torus = G06、manifold = G07。
2. 乗換駅は reading-proofs、sets-maps、metric-space、continuous-map の4つだけ。
3. 第3章の前提は第1章だけ。
4. 情報科学の範囲は9駅(reading-symbols、reading-proofs、sets-maps、convergence、metric-space、cauchy-sequence、completeness、contraction、banach)で、章の順序は 0, 1, 3。第3章の次の章はなし(終着)。第4章は範囲外の章で、次の章はなし。
5. 理論物理の範囲に compact-connected は入らず、章の順序は 0, 1, 2, 3, 4, 5, 6, 8, 9。第3章の次の章は第4章。第7章は範囲外の章で、次の章は第8章。
6. 分野を選んでいないとき、第3章の次の章は第4章、第9章の次の章はなし。
7. 乗換案内:理論物理の第3章は幾何線の1項目(分岐駅 continuous-map は第2章、最初の駅 topological-space は第6章)。理論物理の第1章は2項目(解析線:分岐駅 metric-space はこの章、最初の駅は第3章。幾何線:分岐駅は第2章、最初の駅は第6章)。情報科学の第3章は0項目。
8. 第3章のすべての `[[…]]` と `[[@…]]` が解決する。各章で、原稿の数式(行内の `$…$` と別行立ての `$$…$$`)の数、ビルドが読み取った数式の数、章のページで KaTeX が描画した数式の数が一致する。
