# Feature: 路線図

> **Status:** Draft · Spec-driven kickoff · 2026-11-01
> **Owner:** Taiki Mineno
> **Related:** [build.md](build.md)、[site.md](site.md)、[content-format.md](content-format.md)(路線ファイル)

## Goal

ビルドが章グラフから路線図の SVG を自動で作る。読者は路線図で、各章がどの駅からどの駅までか、今いる章、分野の目標、そこまでに通る駅、まだ書かれていない章を一目で見られ、駅と章の帯から該当する章へ移動できる。執筆者は路線図を手で描かず、調整は路線ファイルの layout だけで行う。

## Non-goals

- 駅の座標を手で指定すること。調整できるのは支線の向き(layout)だけ。
- requires の関係を矢印で描くこと。描くのは路線と駅だけで、前提は乗換駅の印と、章ページの案内([site.md](site.md))で示す。
- 支線から分岐する支線。支線は幹線から分岐するものだけを扱う。
- 未執筆の章を分野の図に描くこと。未執筆の章は分野の範囲に入らないので、全体の図にだけ描く。

## Inputs / Outputs

### 図の種類

| 図 | 描く駅 | 未執筆の章 | 目標の印 | 今の章の強調 | 使う場所 |
|---|---|---|---|---|---|
| 全体の路線図 | すべての駅 | 描く | なし | なし | トップページ |
| 分野の路線図 | 分野の範囲の駅 | 描かない | その分野の目標 | なし | 分野の入口ページ |
| 章ページの路線図 | 分野ごとの図(分野の範囲)と、全体の図 | 全体の図にだけ描く | 分野の図にはその分野の目標 | 今の章 | 章ページ。選んだ分野で出し分ける |

どの図でも、描く駅のある章のすべてに章の帯をかける(「印と凡例」)。章ページには、分野の数 + 1 枚の図を入れる。表示番号は図によって変わらない(分野の図で G03 を描かなくても、G04 は G04 のまま)。

### 分岐駅

支線 L の、ある図での分岐駅は、次のように決める。

1. その図に描く L の駅のうち、読む順で最初の駅を s とする。
2. s の requires が指す駅のうち、幹線にあり、その図に描く駅を集める。
3. その中で読む順が最も後ろの駅を、分岐駅とする。

全体の図では、未執筆の章の駅も描く駅に含める。未執筆の章の最初の駅の requires は、路線ファイルの planned に書いた requires とし、ほかの未執筆の駅の requires は空とする([content-format.md](content-format.md))。

描く駅の集合は requires をさかのぼって閉じていて、requires は読む順で前の駅しか指さない。このため s の requires はすべて L の外の路線にあり、図に描かれている。2 で駅が1つもなければ E12 にする。

分岐駅は図ごとに決まる。分野の図では描く駅が違うので、全体の図と同じ分岐駅になるとは限らない。分岐駅の判定と E12 の検査は、全体の図と、分野ごとの図のそれぞれで行う(章ページの図は、描く駅が全体の図か分野の図と同じなので、配置も同じになる)。

### 配置

1. 幹線を、路線ファイルの順に横一列に並べる。駅は読む順に、左から同じ間隔で置く。未執筆の駅は、章番号の順で読む順に入り、章の中では planned の stations に書いた順に並ぶ。
2. 支線は分岐駅から斜めの線で分かれ、その先で駅を読む順に横一列に並べる。`up` の支線は幹線の上の段に、`down` の支線は下の段に置く。
3. 同じ向きの支線が2本以上あれば、路線ファイルの順に、幹線から遠い段へ置いていく。
4. `right` の支線は、分岐駅がその図の幹線の最後の駅なら、幹線と同じ高さで右へ続ける。そうでなければ `down` と同じに描き、通知 N03 を出す。
5. 駅は表示番号を書いた札で表し、駅名を札の外(上の段では札の上、それ以外では札の下)に書く。駅名が長いときは2行までに折り返す。折り返す位置はツールが決め、「の」「・」の後ろを優先する。
6. 駅の札・線・駅名・印・章の札(帯の文字)は、互いに重ならない。図は横に長くなってよい。ページでは、図の枠の中で図を動かして見る(「図の操作」)。
7. 章の帯は、章の駅の区間を、駅の札・駅名・印ごと囲む。同じ段で隣り合う章の帯は重ならない。章の札は、上の段では駅の札の下、それ以外では駅の札の上に書く。章の境目では、前の章の札と次の章の札が重ならないように駅の間隔を広げる。札の幅は、今の章の札(「第N章 このページ」)か未執筆の章の札(「第N章 未執筆」)の長さで見積もり、どのページでも同じ配置にする。

寸法と線の太さは実装で決める。

### 印と凡例

| 対象 | 描き方 |
|---|---|
| 路線 | 路線ファイルの color の線。ダークテーマでは color_dark(なければ color)。style が `dotted` なら点線。札の枠と表示番号の文字も同じ色にする |
| 終着駅 | 札を路線の色で塗りつぶし、目標の label を札の説明(SVG の `title`)に入れる |
| 途中下車駅 | 「途中下車OK」の札を添え、目標の label を、その札の説明(SVG の `title`)に入れる |
| 乗換駅 | 札の枠を太く濃くする。その図に描く駅どうしで判定する |
| 章 | 描く駅のある章ごとに、その駅の区間に薄い帯をかけ、「第N章」の札を書く |
| 今の章 | 章ページの図では、今の章の帯を強調の色にし、札を「第N章 このページ」にする。今の章の駅が図にないときは、強調する帯はない。強調の色はライトで `#ece8fa`、ダークで `#40366f` とする。ダークは地と帯の明るさの差が小さく見分けにくいので、ライトより強める |
| 未執筆の章 | 全体の図にだけ描く。駅は表示番号のない灰色の札と灰色の駅名で表し、帯は灰色の破線の枠、札は「第N章 未執筆」にする。未執筆の駅へつながる線も灰色にする。乗換駅の判定には使わない |
| 凡例 | 図に出てくる路線と、終着駅・乗換駅の印。途中下車駅があれば途中下車OK の印、未執筆の章があれば未執筆の印も |

### リンク

- 各駅の札は、その駅へのリンク(`<ベースパス>chapters/<章ID>/#<駅ID>`)にする(P-03)。
- 分野の路線図と、章ページの分野の図では、リンクに `?field=<分野ID>` を付ける。全体の図では付けない。
- 章ページの図にある今の章の駅だけは、リンクを `#<駅ID>` だけにし、ページを読み込み直さずにその駅へ移動する。
- 章の帯は、札を含む帯の範囲全体を、その章のページの先頭へのリンク(`<ベースパス>chapters/<章ID>/`)にする。帯の中の駅の札・駅名は、駅へのリンクのまま。駅と同じく、分野の図では `?field=<分野ID>` を付ける。
- 章ページの図の今の章の帯は、そのページの先頭へのリンク(`#`)にし、ページを読み込み直さない。
- ポインタが章の帯の中にある間は、駅の札・駅名・線の上にあっても、その帯を強調の色のままにする。帯の中で線の上を押したときも、帯のリンクで移る(線は押せる対象にしない)。
- 未執筆の章の帯と駅はリンクにしない。
- 駅と章の帯のリンクにはキーボードで移動できる。読み上げでは、駅は表示番号と駅名、章の帯は「第N章 〈章のタイトル〉」が伝わる。

### 図の操作

ページの図は枠の中に置き、読者が動かしたり拡大・縮小したりして見る。

- 枠にはスクロールバーを出さない。図はマウスのドラッグで上下左右に動かす。タッチ操作では横のドラッグで図を動かし、縦のスワイプはページのスクロールに使う。トラックパッドの横方向のスクロールでも図を横に動かす。
- 駅の札や章の帯の上から始めたドラッグでは、離してもリンク先へ移らない。ドラッグせずに押したときだけ移る。
- 枠のすぐ上の右端に「拡大」「縮小」「全体を表示」のボタンを置く(枠の中の図を隠さない)。拡大と縮小は枠の中央を基準に 1.25 倍ずつ変え、倍率は 3 倍まで、縮小は図全体が枠に収まる倍率(0.3 倍より小さければ 0.3 倍)までとする。「全体を表示」は、図全体が枠に収まる倍率(1 倍を超えない)にする。
- 図は枠の外へ逃がさない。図が枠より小さい向きでは、図を枠の中央に置く。
- 枠の高さは、1 倍のときの図の高さとする。開いたときの倍率は、保存した倍率があればその倍率(その図で選べる範囲の外なら、範囲に収める)、なければ 1 倍とする。章ページの図では今の章の帯を枠の横の中央に置く(図の端を越えては動かさない)。それ以外の図は左端から見せる。
- 「拡大」「縮小」「全体を表示」で倍率を変えると、その倍率を読者のブラウザに保存し([site.md](site.md)「ブラウザに保存するもの」)、どのページの図も次に開くときはその倍率で表示する。倍率は全ページの図で1つである。表示の設定の「元に戻す」で消える。
- キーボードで枠の外にある駅や章の帯のリンクにフォーカスしたら、それが枠の中に見えるように図を動かす。ボタンはキーボードで押せる。
- スクリプトが動かないときは、ボタンを出さず、枠の中を横スクロールして見る。

### 代替テキスト

- 図の名前(SVG の `title`):「全体の路線図」「〈分野名〉の路線図」。
- 図の説明(SVG の `desc`):路線ごとに、図に描いたすべての駅を表示番号・駅名・印の順で並べる。未執筆の駅は表示番号を書かず「〈駅名〉(未執筆)」とする。印は「(終着)」「(途中下車OK)」「(乗換)」と書き、2つ以上あれば「(終着・乗換)」のように「・」でつなぐ。例:「解析線:A01 コーシー列、A02 完備性、A03 縮小写像、A04 バナッハの不動点定理(終着)。」

## Failure modes

| コード | きっかけ | 外から見える振る舞い | 直し方 |
|---|---|---|---|
| E12 | 支線の最初の駅が、幹線の駅を前提にしていない(前提がない、または支線の駅だけを前提にしている)。全体の図で支線の最初の駅が未執筆の駅なら、planned の requires で判定する | ビルドが止まり、支線と駅と図の名前を出す | 幹線の駅を requires(未執筆の章なら planned の requires)に足すか、路線の分け方を見直す |
| N03 | `right` の支線の分岐駅が、その図の幹線の最後の駅でない | `down` と同じに描き、支線と図(全体の図か分野の図)の組ごとに通知を1件出す。ビルドは続ける | layout を変えるか、そのままにする |

忘れやすいもの:分野の図では描く駅が分野ごとに違うので、分岐駅・乗換駅・幹線の最後の駅も図ごとに変わる。全体の図だけで確かめても足りない。

## Performance / Safety

- 再現性:同じ章グラフからは同じ SVG ができる。座標は決まった手順で計算し、乱数や実行環境の値を使わない。
- 速度とメモリ:Not load-bearing — no constraint.
