# Feature: 路線図

> **Status:** Draft · Spec-driven kickoff · 2026-11-01
> **Owner:** Taiki Mineno
> **Related:** [build.md](build.md)、[site.md](site.md)、[content-format.md](content-format.md)(路線ファイル)

## Goal

ビルドが章グラフから路線図の SVG を自動で作る。読者は路線図で、今いる章、分野の目標、そこまでに通る駅を一目で見られ、駅から該当する章へ移動できる。執筆者は路線図を手で描かず、調整は路線ファイルの layout だけで行う。

## Non-goals

- 駅の座標を手で指定すること。調整できるのは支線の向き(layout)だけ。
- requires の関係を矢印で描くこと。描くのは路線と駅だけで、前提は乗換駅の印と、章ページの案内([site.md](site.md))で示す。
- 支線から分岐する支線。支線は幹線から分岐するものだけを扱う。
- 図の拡大・縮小などの操作。

## Inputs / Outputs

### 図の種類

| 図 | 描く駅 | 目標の印 | 今の章の強調 | 使う場所 |
|---|---|---|---|---|
| 全体の路線図 | すべての駅 | なし | なし | トップページ |
| 分野の路線図 | 分野の範囲の駅 | その分野の目標 | なし | 分野の入口ページ |
| 章ページの路線図 | 分野ごとの図(分野の範囲)と、全体の図 | 分野の図にはその分野の目標 | 今の章 | 章ページ。選んだ分野で出し分ける |

章ページには、分野の数 + 1 枚の図を入れる。表示番号は図によって変わらない(分野の図で G03 を描かなくても、G04 は G04 のまま)。

### 分岐駅

支線 L の、ある図での分岐駅は、次のように決める。

1. その図に描く L の駅のうち、読む順で最初の駅を s とする。
2. s の requires が指す駅のうち、幹線にあり、その図に描く駅を集める。
3. その中で読む順が最も後ろの駅を、分岐駅とする。

描く駅の集合は requires をさかのぼって閉じていて、requires は読む順で前の駅しか指さない。このため s の requires はすべて L の外の路線にあり、図に描かれている。2 で駅が1つもなければ E12 にする。

分岐駅は図ごとに決まる。分野の図では描く駅が違うので、全体の図と同じ分岐駅になるとは限らない。分岐駅の判定と E12 の検査は、全体の図と、分野ごとの図のそれぞれで行う(章ページの図は、描く駅が全体の図か分野の図と同じなので、配置も同じになる)。

### 配置

1. 幹線を、路線ファイルの順に横一列に並べる。駅は読む順に、左から同じ間隔で置く。
2. 支線は分岐駅から斜めの線で分かれ、その先で駅を読む順に横一列に並べる。`up` の支線は幹線の上の段に、`down` の支線は下の段に置く。
3. 同じ向きの支線が2本以上あれば、路線ファイルの順に、幹線から遠い段へ置いていく。
4. `right` の支線は、分岐駅がその図の幹線の最後の駅なら、幹線と同じ高さで右へ続ける。そうでなければ `down` と同じに描き、通知 N03 を出す。
5. 駅は表示番号を書いた札で表し、駅名を札の外(上の段では札の上、それ以外では札の下)に書く。駅名が長いときは2行までに折り返す。折り返す位置はツールが決め、「の」「・」の後ろを優先する。
6. 駅の札・線・駅名・印・強調の帯の文字は、互いに重ならない。図は横に長くなってよく、ページでは図の枠の中で横にスクロールする。

寸法と線の太さは実装で決める。

### 印と凡例

| 対象 | 描き方 |
|---|---|
| 路線 | 路線ファイルの color の線。ダークテーマでは color_dark(なければ color)。style が `dotted` なら点線。札の枠と表示番号の文字も同じ色にする |
| 終着駅 | 札を路線の色で塗りつぶし、目標の label を札の説明(SVG の `title`)に入れる |
| 途中下車駅 | 「途中下車OK」の札を添え、目標の label を、その札の説明(SVG の `title`)に入れる |
| 乗換駅 | 札の枠を太く濃くする。その図に描く駅どうしで判定する |
| 今の章 | 章の駅の範囲に帯をかけ、「第N章 このページ」と書く。今の章の駅が図にないときは描かない |
| 凡例 | 図に出てくる路線と、終着駅・乗換駅の印。途中下車駅があれば途中下車OK の印も |

### リンク

- 各駅の札は、その駅へのリンク(`<ベースパス>chapters/<章ID>/#<駅ID>`)にする(P-03)。
- 分野の路線図と、章ページの分野の図では、リンクに `?field=<分野ID>` を付ける。全体の図では付けない。
- 章ページの図にある今の章の駅だけは、リンクを `#<駅ID>` だけにし、ページを読み込み直さずにその駅へ移動する。
- 駅のリンクにはキーボードで移動でき、読み上げでは表示番号と駅名が伝わる。

### 代替テキスト

- 図の名前(SVG の `title`):「全体の路線図」「〈分野名〉の路線図」。
- 図の説明(SVG の `desc`):路線ごとに、図に描いたすべての駅を表示番号・駅名・印の順で並べる。印は「(終着)」「(途中下車OK)」「(乗換)」と書き、2つ以上あれば「(終着・乗換)」のように「・」でつなぐ。例:「解析線:A01 コーシー列、A02 完備性、A03 縮小写像、A04 バナッハの不動点定理(終着)。」

## Failure modes

| コード | きっかけ | 外から見える振る舞い | 直し方 |
|---|---|---|---|
| E12 | 支線の最初の駅が、幹線の駅を前提にしていない(前提がない、または支線の駅だけを前提にしている) | ビルドが止まり、支線と駅と図の名前を出す | 幹線の駅を requires に足すか、路線の分け方を見直す |
| N03 | `right` の支線の分岐駅が、その図の幹線の最後の駅でない | `down` と同じに描き、支線と図(全体の図か分野の図)の組ごとに通知を1件出す。ビルドは続ける | layout を変えるか、そのままにする |

忘れやすいもの:分野の図では描く駅が分野ごとに違うので、分岐駅・乗換駅・幹線の最後の駅も図ごとに変わる。全体の図だけで確かめても足りない。

## Performance / Safety

- 再現性:同じ章グラフからは同じ SVG ができる。座標は決まった手順で計算し、乱数や実行環境の値を使わない。
- 速度とメモリ:Not load-bearing — no constraint.

## Acceptance tests

基準原稿で確かめる。

1. 全体の図は21駅を描く。幹線は左から Z01、Z02、M01、M02、M03、M04 の順に並ぶ。解析線(A01〜A08)は M02 から上へ、幾何線(G01〜G07)は M04 から下へ分岐する。
2. 全体の図で乗換駅の印が付くのは Z02、M02、M04 の3駅だけ。
3. 情報科学の図は8駅(Z01、Z02、M01、M02、A01〜A04)を描き、A04 に終着の印がある。幾何線は描かず、凡例に途中下車OK はない。
4. 理論物理の図は20駅を描き、G03 を描かない。A08 と G07 に終着の印、A05 と G06 に途中下車OK の印がある。
5. 理論物理の図の `desc` に「A08 ヒルベルト空間(終着)」が入る。
6. 全体の図、2つの分野の図、全章の章ページの図のそれぞれで、駅の札・駅名・印・帯の文字の外接矩形が互いに重ならない(座標の単体テスト)。
7. 第3章のページの理論物理の図では A01〜A05 に帯がかかり、情報科学の図では A01〜A04 にかかる。第7章のページの理論物理の図には帯がない。
8. 全体の図の G01 のリンクは `/chapters/topological-spaces/#topological-space`、理論物理の図の G01 のリンクは `/chapters/topological-spaces/?field=physics#topological-space` である。
9. 路線ファイルで解析線を `right` にすると、全体の図と理論物理の図では M02 が幹線の最後の駅でないので、解析線は下に描かれ、N03 が2件(全体の図と理論物理の図)出る。情報科学の図では M02 が幹線の最後の駅なので、解析線は幹線と同じ高さで右へ続く。
10. 第10章を足し、そこに layout が `up` の新しい路線を置いて、その最初の駅の requires を hilbert-space だけにすると、E12 で止まる。
11. 全体の図・分野の図・章ページの図を、幅 400px と幅 1200px のスクリーンショットで目視し、文字が読めて重なりがないことを確かめる。ライトとダークの両方で見る。
12. 全体の図で、0番線(Z01–Z02)は点線、本線は実線で描かれる。ダークテーマでは、解析線の線・札の枠・表示番号が color_dark の色になり、本線は color のままになる。
