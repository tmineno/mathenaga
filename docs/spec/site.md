# Feature: 生成するページ(閲覧)

> **Status:** Draft · Spec-driven kickoff · 2026-11-01
> **Owner:** Taiki Mineno
> **Related:** [build.md](build.md)、[route-map.md](route-map.md)、[content-format.md](content-format.md)、[ADR-002](../adr/ADR-002-definition-index.md)

## Goal

読者は、どの分野から来ても、章ページで「今どこにいて、目標まで何が残っているか」を見ながら、章の物語を読み進められる。章ページで分野を選ぶと、ゴール・路線図・次の章・分野での応用がその分野向けに変わる。本文の用語に触れると、ほかの章にある定義もその場で読める。サイトは静的ファイルだけで動く。

## Non-goals

- サーバー側の処理(ログイン、進捗の保存、コメントなど)。覚えるのは選んだ分野だけで、それも読者のブラウザの中に保存する。
- 読み終えた駅の記録や、進み具合の表示。
- サイト内検索(P-06、任意)。公開が済んでから検討する。
- HTML ファイルを直接開く閲覧(file://)。手元ではプレビュー用のサーバー(`npm run dev`)で確かめる。
- テーマの手動切り替え。ライトとダークは OS の設定に従う。
- 印刷用のレイアウト。
- ID を変えたときの、古い URL からの転送。

## Inputs / Outputs

入力はビルドの1段目が作る章グラフと導出値([build.md](build.md))、出力は `dist/` のページと閲覧時のスクリプト・CSS である。

### ページと URL

| ページ | URL | 内容 |
|---|---|---|
| トップページ | `<ベースパス>` | サイト名、全体の路線図、分野の一覧(分野名、紹介文、入口へのリンク) |
| 分野の入口ページ | `<ベースパス>fields/<分野ID>/` | 分野名、紹介文、目標の一覧、分野の路線図、通る章の一覧 |
| 章ページ | `<ベースパス>chapters/<章ID>/` | 章の本文と案内。分野を切り替えて読む |

- 分野は `?field=<分野ID>` で指定する。`#` はページ内のアンカー専用である。
- アンカーは、駅が `#<駅ID>`、定義が `#def-<定義ID>`、定理が `#<定理ID>`、ID を付けた式が `#<式ID>` である。ツールが付けるそれ以外の id は、ID と衝突しない形(`_` で始めるなど)にする。
- どのページも `lang="ja"` で、上端のバーにサイト名「MathEnaga」(トップページへのリンク)を出す。

### 章ページの構成

上端のバー(画面の上に固定する)には、サイト名、章番号とタイトル、分野の切り替え(「指定なし」と各分野)、現在地バー(P-02)を並べる。本文は次の順に並べる。

1. **見出し**:「第N章 · 〈路線名〉 〈最初の駅の表示番号〉–〈最後の駅の表示番号〉」、タイトル、副題。駅が1つだけの章では「第5章 · 解析線 A08」のように表示番号を1つだけ書く。
2. **現在地**:次の4行。
   - 現在地:「〈路線名〉 〈最初の駅の表示番号〉 から 〈最後の駅の表示番号〉 まで」。駅が1つだけなら「〈路線名〉 〈表示番号〉」
   - 前提:章の前提の章へのリンク。なければ「なし」
   - 分野:選んだ分野の名前と入口ページへのリンク。未選択なら「指定なし」
   - 次の章:次の章へのリンク。次の章がなく、この章に選んだ分野の終着駅(kind が final の目標)があれば「なし(この章の 〈表示番号〉 が終着駅)」。終着駅が2つ以上あれば表示番号を「、」で並べる。それ以外で次の章がなければ「なし」。範囲外の章なら「この章は〈分野名〉の範囲外」と添える
3. **分野の選択肢**:未選択のときだけ出す。分野のボタンと、各分野の入口ページへのリンク。
4. **この章のゴール**
5. **路線図**:章ページの路線図([route-map.md](route-map.md))。今の章が選んだ分野の図に載らないときは、図の下に「この章は〈分野名〉の路線図に載っていません」と書く。
6. **出発点**:motivation と、章頭の地の文。
7. **駅**:読む順に並べる。
8. **ふりかえり**
9. **確認問題**:question と、折りたたんだ answer の組。question が1つもない章では、見出しごと出さない。
10. **この先**:下の「この先」。

### 駅の表示

- 見出しには、表示番号の札と駅名を出す。駅と ID を共有する定義があれば、その en を添える。
- その駅が分野の目標なら、目標の印(終着駅・途中下車OK)、分野名、label を添える。分野を選んでいるときは、選んだ分野の目標だけを出す。
- 範囲外の駅には「この分野の目標には不要(読み飛ばし可)」と示し、駅全体を薄く表示する。
- ブロックは、要素名を札にして書いた順に表示する。definition は「定義 · 〈name〉 〈en〉」、theorem は「定理 · 〈name〉」、application は「分野での応用(〈分野名〉) · 〈title〉」の札にする。proof は「証明の詳細」、answer は「答え」の見出しで折りたたむ。
- application は駅の末尾にまとめる。

### 式番号の表示

- 別行立ての式の右端に、式番号「(3.1)」を縦の中央にそろえて出す。
- 式が画面の幅に収まらず式の枠の中で横にスクロールするときも、式番号はスクロールさせずに見えたままにする。
- 番号は分野の選択で変わらない。折りたたんだ分野版や証明の詳細の中の式にも番号があるので、開いている部分だけを見ると番号がとびとびになることがある。
- 用語ポップアップの中の定義の式にも、章ページと同じ番号を出す。

### 分野の切り替えと表示規則(P-05)

ページを開いたときに表示する分野は、次の順で決める。

1. `?field=` の値が分野の ID なら、その分野。分野の ID でなければ、指定がないものとして扱う。
2. 前回選んだ値(`localStorage` の `mathenaga-field`)が分野の ID ならその分野、「指定なし」なら未選択。
3. どちらもなければ未選択。

- 分野か「指定なし」を選ぶと、ページを読み込み直さずに表示を切り替え、選んだ値を保存し、URL の `?field=` を書き換える(指定なしなら消す)。アンカーとほかのクエリは残す。
- `?field=` で開いたときも、その分野を保存する。
- `localStorage` が使えないときも切り替えは動く。次のページに分野が引き継がれるのは、`?field=` を付けたリンク(下)をたどったときだけになる。
- スクリプトが動かないときは、未選択の表示になる。生成する HTML の初期状態を未選択にしておく。
- 章ページの中で分野ごとに出し分ける部分(現在地の「次の章」、この先、乗換案内、分野の路線図)のリンクには、その分野の `?field=<分野ID>` を付ける。分野によらない部分(現在地の「前提」、本文の参照、全体の路線図)のリンクには付けない。今の章の駅へのリンクは `#<駅ID>` だけにする。

| 要素 | 分野を選んでいる | 未選択 |
|---|---|---|
| ゴール・出発点の共通版 | 表示する | 表示する |
| 選んだ分野のゴール・出発点 | 共通版の後に続けて表示する | — |
| 選んだ分野の応用 | 開いて表示する | — |
| ほかの分野の版(ゴール・出発点・応用) | 折りたたんで表示する | すべて折りたたんで表示する |
| 路線図 | 選んだ分野の図に、今の章の帯 | 全体の図に、今の章の帯 |
| 次の章・この先 | 選んだ分野の規則 | 分野を選ばないときの規則 |
| 範囲外の駅 | 印を付けて薄く表示する | 印を付けない |
| 分野の選択肢 | 出さない | 出す |

折りたたんだ分野版には「この章のゴール(〈分野名〉)」のように分野名を付け、開けば読めるようにする。分野版は、分野の並び(ファイル名の文字コード順。[content-format.md](content-format.md) の分野ファイル)の順に並べる。

### この先

分野を選んでいるときは、次の項目をこの順に並べる。

1. この章にその分野の目標があれば、目標ごとに1項目。終着駅は「終着駅:〈分野名〉の目標「〈label〉」には、この章の 〈表示番号〉 で到着します。」、途中下車駅は「途中下車:〈label〉。この章の 〈表示番号〉 で降りて構いません。」
2. 次の章があれば「〈次の章の路線名〉を進む:第N章 〈タイトル〉」。なければ、分野を選ばないときの次の章を「さらに進む場合:第N章 〈タイトル〉(〈分野名〉の範囲外)」として出す(それもなければ出さない)。
3. 乗換案内の項目([build.md](build.md))。分岐駅がこの章にないときは「〈支線名〉に乗り換える:〈分岐駅の表示番号〉 〈駅名〉(第M章)から、第N章 〈タイトル〉へ」、この章にあるときは「〈支線名〉に乗り換える:この章の 〈分岐駅の表示番号〉 〈駅名〉 から、第N章 〈タイトル〉へ」。

未選択のときは「次の章:第N章 〈タイトル〉」(なければ「なし」)と、「分野を選ぶと、その分野の目標までの道順が表示されます。」を出す。

### 分野の入口ページ

- 分野名、紹介文(description)。
- 目標の一覧:目標ごとに、印(終着駅・途中下車OK)、表示番号、駅名、label。
- 分野の路線図。
- 通る章の一覧:分野内の章の順序で、章ごとに「第N章 〈タイトル〉」(章ページへのリンク。`?field=<分野ID>` を付ける)と、その章で分野の範囲に入る駅の表示番号を出す。駅が章の中で続いていれば「A01–A04」、とびとびなら「A01、A03」、1駅なら「A08」と書く。

### 閲覧時の機能

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| P-01 | 用語ポップアップ | 下の「用語ポップアップ」 | 必須 |
| P-02 | 現在地バー | 上端のバーに、この章の駅の表示番号を並べる。スクロールに合わせて、読んでいる駅を強調する。押すとその駅へ移動する。範囲外の駅は薄くする | 必須 |
| P-03 | 路線図の移動 | 路線図の駅から、該当する章と駅へ移動できる([route-map.md](route-map.md)) | 必須 |
| P-04 | 折りたたみ | 証明の詳細、確認問題の答え、ほかの分野の版を折りたたむ。キーボードで開閉できる | 必須 |
| P-05 | 分野の切り替え | 上の「分野の切り替えと表示規則」 | 必須 |
| P-06 | サイト内検索 | 用語・定理名で章を探せる。今回は作らない(Non-goals) | 任意 |

**用語ポップアップ**:

- 本文の用語(定義への `[[…]]`)にポインターを重ねる、フォーカスする、タップすると、ポップアップに定義を出す。用語はボタンにして、キーボードで操作できるようにする。
- 中身は、表示番号、定義の name、en、定義の本文、「定義の場所:第N章 〈タイトル〉 · 〈表示番号〉 〈駅名〉」と、定義の場所への移動である。定義が同じページにあれば「この定義へ移動」でページ内を移動し、ほかのページにあれば章ページの定義へのリンクにする。
- 定義は、最初にポップアップを開くときに `defs.json` を一括で取得し、以後は取得し直さない([ADR-002](../adr/ADR-002-definition-index.md))。取得中は「読み込み中…」、失敗したら「定義を読み込めませんでした」と出し、次に開くときにもう一度取得する。
- Esc、ポップアップと用語の外を押す、ポインターが用語とポップアップから離れる(少し待ってから)のどれかで閉じる。

## Failure modes

| きっかけ | 外から見える振る舞い | 回復 |
|---|---|---|
| `defs.json` を取得できない(通信の失敗など) | ポップアップに「定義を読み込めませんでした」と出る。本文は読める | 次にポップアップを開くときに取得し直す |
| `defs.json` に定義がない(ビルドの不具合) | ポップアップに「定義が索引にありません」と出る | ビルドの不具合として直す。同じビルドの出力なら起きない |
| `?field=` が分野の ID でない | 指定がないものとして、前回の値か未選択で表示する | なし |
| `localStorage` が使えない(プライベートモードなど) | 切り替えはそのページの中だけで動く | なし |
| Google Fonts を読み込めない(通信の失敗、遮断など) | システムの書体で表示する。レイアウトは崩れず、本文と数式は読める | なし |
| スクリプトが動かない | 未選択の表示になる。折りたたみは HTML の機能なので動く。ポップアップと現在地バーの強調は動かない | なし |
| 今の章が選んだ分野の図に載らない(忘れやすい) | 帯のない図と「この章は〈分野名〉の路線図に載っていません」が出る | なし |
| 幅の狭い画面で長い数式・表・コードがはみ出す(忘れやすい) | その要素の中だけで横にスクロールする。式番号は見えたまま | なし |

## Performance / Safety

| 項目 | 要件 |
|---|---|
| 配信 | 静的ファイルのみ。閲覧時に読みに行くデータは同じサイトの `defs.json` だけ(ページが読み込む CSS・スクリプト・フォント・図を除く)。サイトの外から読み込むのは、Google Fonts の CSS と書体だけ |
| 閲覧環境 | PC とスマートフォン(幅 400px 程度)。ページ全体の横スクロールは出さない。横スクロールしてよいのは、路線図・表・別行立ての数式・コードブロックの内側だけ |
| テーマ | ライトとダークの両方に対応し、OS の設定(`prefers-color-scheme`)に従う |
| アクセシビリティ | キーボードで全機能を操作できる。フォーカスの位置が見える。路線図に代替テキストを付ける。動きを減らす設定のときは、スクロールのアニメーションをしない |
| 書体 | 日本語の長文を読みやすい書体(BIZ UDPGothic などの UD フォント)を、Google Fonts から読み込む。書体の指定には代わりの書体を並べ、Google Fonts を読み込めないときはシステムの書体で表示する。数式の書体(KaTeX)は自前で配信する([build.md](build.md)) |
| 安全 | ページは外部のスクリプトを読み込まない |
| 速度 | Not load-bearing — no constraint |

## Acceptance tests

基準原稿をベースパス `/` でビルドし、Playwright でブラウザを動かして確かめる。どれも `npm test` に含め、CI で実行する([build.md](build.md))。

1. 第3章を `?field=physics` で開くと、ゴールは共通版の後に理論物理の版が続き、情報科学の版は折りたたまれている。路線図は理論物理の図で、A01〜A05 に帯がかかる。次の章は第4章。範囲外の印は1つもない。completeness 駅では理論物理の応用が開き、情報科学の応用が折りたたまれている。contraction 駅には情報科学の応用だけが折りたたまれて出る。picard-lindelof 駅に途中下車OK の印(理論物理)が付く。この先に、幾何線への乗換案内(M04 連続写像、第2章 → 第6章)が出る。
2. 第3章を `?field=cs` で開くと、ゴールは共通版の後に情報科学の版が続く。路線図は情報科学の図で、A01〜A04 に帯がかかる。次の章は「なし(この章の A04 が終着駅)」。この先に、A04 で終着する案内と「さらに進む場合:第4章 ノルムと内積(情報科学の範囲外)」が出て、乗換案内は出ない。picard-lindelof 駅は範囲外の印が付いて薄く表示される。
3. 保存した値がない状態で第3章を `?field=` なしで開くと、ゴールと出発点は共通版だけが開き、分野版はすべて折りたたまれている。全体の図に帯がかかり、次の章は第4章で、分野の選択肢が出る。
4. 保存した値が physics の状態で第3章を `?field=xyz` で開くと、理論物理で表示される。
5. 未選択の第3章で「情報科学」を選ぶと、URL が `?field=cs` になる。ページを読み込み直しても、第4章へ移っても情報科学のまま。「指定なし」を選ぶと `?field=` が消える。
6. スクリプトを止めて第3章を開くと、3 と同じ表示になる。
7. 第3章の completeness 駅の定義の中の「コーシー列」にフォーカスすると、ポップアップに A01・コーシー列・Cauchy sequence と定義の本文が出て、「この定義へ移動」で `#def-cauchy-sequence` に移る。cauchy-sequence 駅の「点列の収束」では、定義の場所が第1章と出て、`/chapters/convergence-metric/#def-convergence` へのリンクになる。ページを開いてから閉じるまでに `defs.json` の取得は1回だけ。
8. 第3章で banach 駅までスクロールすると、現在地バーの A04 が強調される。`?field=cs` では A05 が薄い。
9. 全体の図の G01 を押すと `/chapters/topological-spaces/#topological-space` に移る。
10. 幅 400px で全ページを開くと、ページ全体の横スクロールが出ない(`document.documentElement.scrollWidth` が `clientWidth` を超えない)。
11. OS の設定をダークにすると、全ページがダークの配色で表示される。
12. キーボードだけで、分野の切り替え、用語ポップアップの開閉、折りたたみの開閉、路線図の駅への移動、現在地バーの移動ができる。
13. 理論物理の入口ページには目標が4件あり、通る章は第0、1、2、3、4、5、6、8、9章。第3章の行は「A01–A05」で、リンク先は `/chapters/completeness-fixed-point/?field=physics`。情報科学の入口ページの第3章の行は「A01–A04」。
14. 理論物理を選んで第7章を開くと、現在地に「この章は理論物理の範囲外」が出て、次の章は第8章。全駅に範囲外の印が付く。
15. 第3章の別行立ての式の右端に (3.1)〜(3.14) が出る。幅 400px で、banach 駅の証明の詳細を開き、横にスクロールする長い式を端までスクロールしても、その式番号は見えたままである。`?field=physics` と `?field=cs` で開き直しても、同じ式の番号は変わらない。
16. Google Fonts への通信を遮断して第3章を開くと、本文はシステムの書体で表示され、数式は KaTeX の書体で描画される。ページのスクリプトはエラーを出さず、10 と同じく横スクロールが出ない。
