# Feature: 生成するページ(閲覧)

> **Status:** Draft · Spec-driven kickoff · 2026-11-01
> **Owner:** Taiki Mineno
> **Related:** [build.md](build.md)、[route-map.md](route-map.md)、[content-format.md](content-format.md)、[ADR-002](../adr/ADR-002-definition-index.md)、[ADR-005](../adr/ADR-005-notes-and-references.md)

## Goal

読者は、どの分野から来ても、章ページで「今どこにいて、目標まで何が残っているか」を見ながら、章の物語を読み進められる。章ページで分野を選ぶと、ゴール・路線図・次の章・分野での応用がその分野向けに変わる。本文の用語に触れると、ほかの章にある定義もその場で読める。テーマ・文字の大きさ・本文の幅などの表示を読者が選べ、気になる駅をしおりに入れて、どのページからでもその駅へ戻れる。サイトは静的ファイルだけで動く。

## Non-goals

- サーバー側の処理(ログイン、進捗の保存、コメントなど)。覚えるのは選んだ分野、表示の設定(P-09)、しおり(P-10)、路線図の倍率だけで、どれも読者のブラウザの中に保存する。ほかの機器やブラウザには引き継がない。改善案は GitHub Issue の作成画面へのリンクで受け付け(P-07)、サイトでは何も保存しない。
- 読み終えた駅の記録や、進み具合の表示。
- サイト内検索(P-06、任意)。公開が済んでから検討する。
- HTML ファイルを直接開く閲覧(file://)。手元ではプレビュー用のサーバー(`npm run dev`)で確かめる。
- 章ページの路線図の折りたたみ。
- 印刷用のレイアウト。
- ID を変えたときの、古い URL からの転送。

## Inputs / Outputs

入力はビルドの1段目が作る章グラフと導出値([build.md](build.md))、出力は `dist/` のページと閲覧時のスクリプト・CSS である。

### ページと URL

| ページ | URL | 内容 |
|---|---|---|
| トップページ | `<ベースパス>` | ロゴ(サイト名を含む)、全体の路線図、分野の一覧(分野名、紹介文、入口へのリンク) |
| 分野の入口ページ | `<ベースパス>fields/<分野ID>/` | 分野名、紹介文、目標の一覧、分野の路線図、通る章の一覧 |
| 章ページ | `<ベースパス>chapters/<章ID>/` | 章の本文と案内。分野を切り替えて読む。未執筆の章(路線ファイルの planned)にはページを作らない |

- 分野は `?field=<分野ID>` で指定する。`#` はページ内のアンカー専用である。
- アンカーは、駅が `#<駅ID>`、定義が `#def-<定義ID>`、定理が `#<定理ID>`、ID を付けた式が `#<式ID>`、ID を付けた図が `#<図ID>`、ID を付けた応用が `#<応用ID>`、章ページの参考文献の項目が `#<文献ID>` である。アンカーの指す要素が折りたたみ(応用・証明の詳細・答え・分野版)の中にあれば、その折りたたみを開いて表示する。ツールが付けるそれ以外の id(注の印 `#_note-N` と注の一覧の項目 `#_note-N-text` など)は、ID と衝突しない形(`_` で始めるなど)にする。
- どのページも `lang="ja"` で、上端のバーにロゴの鳥とサイト名「MathEnaga」(トップページへのリンク)を出し、favicon を指定する(下の「ロゴと favicon」)。

### ロゴと favicon

- ロゴはドット絵で、元データは `src/site/assets/logo.txt` である。1 文字が 1 ドットで、`#` が線、`.` が透明。全行を同じ長さで書く。鳥の絵とサイト名の文字を、線のドットがない行で上下に区切って並べる。
- 鳥は、線を `#18202e` で、線で囲まれた体の内側と、線の外側 1 ドット(斜めの隣も含む)の縁を白で塗る。色はテーマによらず同じにする。白い縁があるので、暗い背景でも線と尾が溶けない。縁の外は透明。
- トップページの見出しはロゴ全体にする。サイト名の文字の色は本文の文字色で、テーマに従う。1 ドットを 3px で表示し、鳥の縁の分として上下左右に 1 ドットずつ余白をとる(88×80 ドット、264×240px)。読み上げる名前は「MathEnaga」にする。
- 上端のバーでは、サイト名の左にロゴの最初の塊(鳥)を、縁を含めて高さ 32px で出す。リンクの文字がサイト名なので、鳥は読み上げない。
- favicon は、縁を含めた鳥を 66×66 の正方形の中央に置いたもので、SVG と PNG を出す。色は上の鳥と同じで、ダークでも切り替えない。
- README の見出しはバナーにする。ロゴの鳥とサイト名の文字を同じドットの大きさで横に並べ、あいだを 14 ドット空け、文字を鳥の高さの中央に置く。鳥の塗りはサイトの鳥と同じ(上)で、文字は `#6e7781` にする。縁の外は透明。テーマで画像を切り替える `<picture>` は閲覧環境によって切り替わらないことがあったので使わず、1 枚の SVG(`docs/assets/banner.svg`)を白地でも暗い地でも読める色にする(文字のコントラストは白地で 4.55、GitHub の暗い地 `#0d1117` で 4.16)。1 ドットを 2px で表示し(332×118px)、代替テキストは「MathEnaga」にする。SVG は `npm run banner` で `logo.txt` から作る。

### 章ページの構成

上端のバー(画面の上に固定する)には、サイト名、章番号とタイトル、分野の切り替え(「指定なし」と各分野)、現在地バー(P-02)を並べる。本文は次の順に並べる。

1. **見出し**:「第N章 · 〈路線名〉 〈最初の駅の表示番号〉–〈最後の駅の表示番号〉」、タイトル、副題。駅が1つだけの章では「第5章 · 解析線 A08」のように表示番号を1つだけ書く。
2. **現在地**:次の4行。
   - 現在地:「〈路線名〉 〈最初の駅の表示番号〉 から 〈最後の駅の表示番号〉 まで」。駅が1つだけなら「〈路線名〉 〈表示番号〉」
   - 前提:章の前提の章へのリンク。なければ「なし」
   - 分野:選んだ分野の名前と入口ページへのリンク。未選択なら「指定なし」
   - 次の章:次の章へのリンク。次の章がなく、この章に選んだ分野の最終目標(kind が final の目標)があれば「なし(この章の 〈表示番号〉 が最終目標)」。最終目標が2つ以上あれば表示番号を「、」で並べる。それ以外で次の章がなければ「なし」。範囲外の章なら「この章は〈分野名〉の範囲外」と添える
3. **分野の選択肢**:未選択のときだけ出す。分野のボタンと、各分野の入口ページへのリンク。
4. **この章のゴール**
5. **路線図**:章ページの路線図([route-map.md](route-map.md))。今の章が選んだ分野の図に載らないときは、図の下に「この章は〈分野名〉の路線図に載っていません」と書く。
6. **出発点**:見出し「出発点」の下に、motivation と章頭の地の文を置く。見出しと重ならないよう、共通版には札を付けず、分野版の札(折りたたんだときの見出し)は「〈分野名〉では」とする。
7. **駅**:読む順に並べる。
8. **ふりかえり**
9. **確認問題**:question と、折りたたんだ answer の組。question が1つもない章では、見出しごと出さない。
10. **参考文献**:章の参考文献([build.md](build.md))。文献を1つも引いていない章では、見出しごと出さない(下の「注と参考文献の表示」)。
11. **この先**:下の「この先」。

### 駅の表示

- 見出しには、表示番号の札と駅名を出す。駅と ID を共有する定義があれば、その en を添える。
- その駅が分野の目標なら、目標の印(最終目標・途中の目標)、分野名、label を添える。分野を選んでいるときは、選んだ分野の目標だけを出す。
- 範囲外の駅には「この分野の目標には不要(読み飛ばし可)」と示し、駅全体を薄く表示する。
- summary は、札も枠も付けず、駅の見出し(と目標の印)のすぐ後の地の文として表示する。
- ほかのブロックは、要素名を札にして書いた順に表示する。definition は「定義 〈番号〉 · 〈name〉 〈en〉」、theorem は「定理 〈番号〉 · 〈name〉」(番号は [build.md](build.md)「導出する値」の定義と定理の番号)、application は「応用 〈番号〉(〈分野名〉) · 〈title〉」の札にする(番号は [build.md](build.md)「導出する値」の応用番号)。proof は「証明の詳細」、answer は「答え」の見出しで折りたたむ。
- theorem の直後に続く proof-sketch と proof(あいだにほかのブロックや地の文を挟まないもの)は、定理の枠の中の、定理の本文の後に書いた順に入れる。proof-sketch は「証明の骨格」の札を付けて本文と線で区切り、proof は「証明の詳細」の札(定理の札と同じ大きさ)を見出しにして折りたたむ。定理の直後にないものは、ほかのブロックと同じく単独の枠で表示する。
- application は駅の末尾にまとめる。
- remark は「補足」の札の枠で、書いた位置に表示する。折りたたまない。
- 駅に注があれば、駅の最後(application の後)に注の一覧を置く(下の「注と参考文献の表示」)。

### 式番号の表示

- 別行立ての式の右端に、式番号「(3.1)」を縦の中央にそろえて出す。
- 式が画面の幅に収まらず式の枠の中で横にスクロールするときも、式番号はスクロールさせずに見えたままにする。
- 番号は分野の選択で変わらない。折りたたんだ分野版や証明の詳細の中の式にも番号があるので、開いている部分だけを見ると番号がとびとびになることがある。
- 用語ポップアップの中の定義の式にも、章ページと同じ番号を出す。

### 図の表示

- 図([content-format.md](content-format.md)「図」)は本文の段の中央に置く。画像が2つ以上の図は横に並べ、段の幅に収まらなければ折り返して縦に積む。各画像の下に (a)、(b)、… の札を出す。
- 図の下の中央に、図番号「図 3.1」とキャプションを出す。図番号は分野の選択で変わらない。
- 画像は段の幅より大きく表示しない。

### 注と参考文献の表示

**注**:

- 注(`^[…]`)を書いた位置に、上付きの印「注N」(N は注番号。[build.md](build.md))を置く。数式の `x^*` などの上付きと見分けるため、印には番号だけでなく「注」の字を付ける。
- 注を書いた駅か節(「この章のゴール」「出発点」「ふりかえり」「確認問題」)の最後に、見出し「注」の下に、その駅か節の注を注番号の順に並べる。駅では application の後に置く。各項目は「注N」、空白、注の本文、印へ戻るリンク(「↩」。読み上げは「本文へ戻る」)である。
- 印は、注の一覧の項目へのリンク(`#_note-N-text`)にする。スクリプトが動くときは、印にポインターを重ねる、フォーカスする、押すとポップアップに注の本文を出し、押しても一覧へは移らない。ポップアップの中身は一覧の項目と同じで、用語はボタンにせず文字だけにする。閉じ方は用語ポップアップと同じである。
- 注の本文は章ページの中にあるので、ポップアップのために取得するデータはない。

**参考文献**:

- 本文の `[[@文献ID]]` は「[N]」(N は文献番号)と表示し、章末の参考文献の項目(`#<文献ID>`)へのリンクにする。スクリプトが動くときは、ポインターを重ねる、フォーカスする、押すとポップアップに書誌を出し、押しても項目へは移らない。ポップアップには「参考文献へ移動」のリンクを置く。
- 章末の「参考文献」の節には、章の参考文献を「[N] 〈書誌〉」の形で並べる。書誌は次の形にする。
  - 本:著者、書名、版、出版社、年。巻(volume)があれば、書名の後に空白を挟んで置き、書名と一緒に『』で囲むかイタリックにする(『解析入門 II』)。
  - 論文:著者、題名、雑誌名、巻(号)、ページ、年。
  - 要素は「、」で区切り、最後に「。」を付ける。書いていない要素(版、号など)は飛ばす。
  - 著者は「、」でつなぎ、4人以上なら最初の1人の後に「ほか」と書く。
  - 書名・題名に、ひらがな・カタカナ・漢字があれば和文として扱い、書名は『』、論文の題名は「」で囲む。なければ欧文として扱い、書名と雑誌名をイタリックにし、論文の題名は “” で囲む。
  - 「。」の後に、ISBN があれば「ISBN 〈一覧に書いた ISBN〉」を、DOI があれば `https://doi.org/<DOI>` へのリンクを、この順に空白で区切って置く。
- 表示の設定の「用語ポップアップ」(P-09)は、注と文献のポップアップにも効く。

### 分野の切り替えと表示規則(P-05)

ページを開いたときに表示する分野は、次の順で決める。

1. `?field=` の値が分野の ID なら、その分野。分野の ID でなければ、指定がないものとして扱う。
2. 前回選んだ値(`localStorage` の `mathenaga-field`)が分野の ID ならその分野、「指定なし」なら未選択。
3. どちらもなければ未選択。

- 分野か「指定なし」を選ぶと、ページを読み込み直さずに表示を切り替え、選んだ値を保存し、URL の `?field=` を書き換える(指定なしなら消す)。アンカーとほかのクエリは残す。
- `?field=` で開いたときも、その分野を保存する。
- `localStorage` が使えないときも切り替えは動く。次のページに分野が引き継がれるのは、`?field=` を付けたリンク(下)をたどったときだけになる。
- スクリプトが動かないときは、未選択の表示になる。生成する HTML の初期状態を未選択にしておく。
- 章ページの中で分野ごとに出し分ける部分(現在地の「次の章」、この先、乗換案内、分野の路線図)のリンクには、その分野の `?field=<分野ID>` を付ける。分野によらない部分(現在地の「前提」、本文の参照、全体の路線図)のリンクには付けない。今の章の駅へのリンクは `#<駅ID>` だけにする。

| 要素 | 分野を選んでいる | 未選択 |
|---|---|---|
| ゴール・出発点の共通版 | 表示する | 表示する |
| 選んだ分野のゴール・出発点 | 共通版の後に続けて表示する | — |
| 選んだ分野の応用 | 駅ごとに最初の1つを開いて表示する。同じ分野の2つ目以降は、ほかの分野の版と同じく折りたたむ | — |
| ほかの分野の版(ゴール・出発点・応用) | 折りたたんで表示する | すべて折りたたんで表示する |
| 路線図 | 選んだ分野の図に、今の章の帯 | 全体の図に、今の章の帯 |
| 次の章・この先 | 選んだ分野の規則 | 分野を選ばないときの規則 |
| 範囲外の駅 | 印を付けて薄く表示する | 印を付けない |
| 分野の選択肢 | 出さない | 出す |

折りたたんだ分野版には「この章のゴール(〈分野名〉)」のように分野名を付け、開けば読めるようにする。分野版は、分野の並び(ファイル名の文字コード順。[content-format.md](content-format.md) の分野ファイル)の順に並べる。

### この先

分野を選んでいるときは、次の項目をこの順に並べる。

1. この章にその分野の目標があれば、目標ごとに1項目。最終目標は「最終目標:〈分野名〉の目標「〈label〉」には、この章の 〈表示番号〉 で到達します。」、途中の目標は「途中の目標:〈label〉。この章の 〈表示番号〉 で読み終えて構いません。」
2. 次の章があれば「〈次の章の路線名〉を進む:第N章 〈タイトル〉」。なければ、分野を選ばないときの次の章を「さらに進む場合:第N章 〈タイトル〉(〈分野名〉の範囲外)」として出す(それもなければ出さない)。
3. 乗換案内の項目([build.md](build.md))。「〈支線名〉に乗り換える:〈分岐駅〉から、第N章 〈タイトル〉へ」と書く。〈分岐駅〉は、この章にない分岐駅を「〈表示番号〉 〈駅名〉(第M章)」、この章にある分岐駅を「この章の 〈表示番号〉 〈駅名〉」と書き、2つ以上あれば読む順に「・」でつなぐ(例:「この章の A08 ヒルベルト空間・G07 多様体(第9章)から」)。

未選択のときは「次の章:第N章 〈タイトル〉」(なければ「なし」)と、「分野を選ぶと、その分野の目標までの道順が表示されます。」を出す。

### 分野の入口ページ

- 分野名、紹介文(description)。
- 目標の一覧:目標ごとに、印(最終目標・途中の目標)、表示番号、駅名、label。
- 分野の路線図。
- 通る章の一覧:分野内の章の順序で、章ごとに「第N章 〈タイトル〉」(章ページへのリンク。`?field=<分野ID>` を付ける)と、その章で分野の範囲に入る駅の表示番号を出す。駅が章の中で続いていれば「A01–A04」、とびとびなら「A01、A03」、1駅なら「A08」と書く。

| P-11 | 注と文献のポップアップ | 上の「注と参考文献の表示」 | 必須 |
| P-12 | 選んだ文章からの起票と原稿の表示 | 下の「選んだ文章からの起票と原稿の表示」 | 必須 |

**改善案の起票**:

- ビルドに `MATHENAGA_REPO_URL`(GitHub のリポジトリの URL。[build.md](build.md))を渡したときだけ、章ページの各駅に起票のアイコン(吹き出し)を1つずつ出す。渡さなければ出さない。
- アイコンは、ポインターが駅の中にある間と、駅の中にキーボードのフォーカスがある間だけ見える。ホバーのできない画面(タッチ操作)では、常に薄く見せる。
- 起票のアイコンは、しおりのアイコン(P-10)の右に横に並べる。本文の段の右に余白がある幅(段の幅に 180px を足した幅以上。標準の段の幅では 1340px 以上)では、2つのアイコンを駅の右の余白に置き、駅を読み進めても上端のバーのすぐ下にとどまる。それより狭い幅では、駅の見出しの行の右端に置き、見出しの文字にかからないようにする。
- アイコンに重ねるかフォーカスすると「この駅についてGitHub Issueに起票する」と出る。読み上げも同じ文にする。
- 押すと、新しいタブで GitHub の Issue 作成画面を開く。Issue フォーム(`.github/ISSUE_TEMPLATE/station.yml`)を使い、次の欄を埋めておく。種類(誤り・分かりにくい・足りない・その他)と内容は読者が書く。
  - タイトル:「[改善案] 第N章 〈表示番号〉 〈駅名〉」
  - 駅:「第N章 〈章のタイトル〉 / 〈表示番号〉 〈駅名〉(〈駅ID〉)」
  - ページ:その駅の URL(`<オリジン><ベースパス>chapters/<章ID>/#<駅ID>`)。スクリプトが動かないときは、オリジンを除いたパスにする
- Issue を立てるには GitHub へのログインが要る。ログインは GitHub の画面で行い、サイトは関わらない。

**選んだ文章からの起票と原稿の表示**:

- `MATHENAGA_REPO_URL` を渡したビルドだけで、選択メニュー(下の「位置情報つきのコピー」)の区切りの線の右に「起票」と「編集」を出す。どちらもリンクで、押すと新しいタブで GitHub を開き、選択メニューを閉じる。
- 「起票」は、改善案の起票と同じ Issue フォームの作成画面を開き、次の欄を埋めておく。区画は、選んだ範囲の位置(下の「位置情報つきのコピー」)の区画とする。種類と内容は読者が書く。
  - 駅の中:タイトル・駅・ページは、その駅の起票のアイコンと同じ。
  - 駅の外の節:タイトル「[改善案] 第N章 〈節の名前〉」、駅「第N章 〈章のタイトル〉 / 〈節の名前〉」、ページはその節の URL。この章のゴールは章ページの URL、出発点・ふりかえり・確認問題・参考文献は、章ページの URL に `#_start`・`#_review`・`#_quiz`・`#_references` を付けたもの。
  - 該当箇所:「位置つき」でコピーするのと同じ文(1行目に位置、2行目から選んだ文)。選んだ文が 500 文字を超えるときは、先頭の 500 文字の後に「…」を付けて切る。Issue 作成画面の URL が長すぎて GitHub に断られないようにするためである。
- 「編集」は、原稿のファイルを GitHub で行番号つきで開き、選んだ範囲にかかる段落の行を強調する。編集は、開いた画面の GitHub の編集のボタン(鉛筆)から行う。
  - URL は `<リポジトリの URL>/blob/main/content/chapters/<章フォルダ名>/index.md?plain=1#L<始め>-L<終わり>`。始めと終わりが同じなら `#L<行>` にする。`?plain=1` は、GitHub が Markdown を整形せずに行番号つきで表示するための指定である。
  - 始めと終わりは、選んだ範囲にかかる段落(位置情報つきのコピーで数える段落と、駅の見出し)が原稿のファイルで占める行のうち、最初の行と最後の行(1 から数え、front matter の行も数える)。注の一覧の項目は、その注を書いた段落の行とする。文字を1つも選んでいない段落は数えない(段落を3回押して選ぶと、範囲の終わりが次の段落の頭になることがある)。行はビルドが段落ごとに書き込む。
  - 参考文献の項目と節の見出し(「出発点」など、原稿に書かない見出し)には行がない。選んだ範囲に行のある段落が1つもないときは、「編集」を出さない。
  - 原稿は main の版を指す。公開は main への push のたびに作り直すので、公開中のページの行と main の原稿の行はそろう。
- 原稿の書き換えにも GitHub へのログインが要る。書き込みの権限がなければ、GitHub がフォークを作る案内を出す。サイトは関わらない。

**用語ポップアップ**:

- 本文の用語(定義への `[[…]]`)にポインターを重ねる、フォーカスする、タップすると、ポップアップに定義を出す。用語はボタンにして、キーボードで操作できるようにする。
- 中身は、表示番号、「定義 〈番号〉 · 〈name〉」、en、定義の本文、「定義の場所:第N章 〈タイトル〉 · 〈表示番号〉 〈駅名〉」と、定義の場所への移動である。定義が同じページにあれば「この定義へ移動」でページ内を移動し、ほかのページにあれば章ページの定義へのリンクにする。
- 定義は、最初にポップアップを開くときに `defs.json` を一括で取得し、以後は取得し直さない([ADR-002](../adr/ADR-002-definition-index.md))。取得中は「読み込み中…」、失敗したら「定義を読み込めませんでした」と出し、次に開くときにもう一度取得する。
- Esc、ポップアップと用語の外を押す、ポインターが用語とポップアップから離れる(少し待ってから)のどれかで閉じる。

**位置情報つきのコピー**:

- 章ページの本文を選ぶと、選んだ範囲のすぐ下に、ボタンを1行に並べた帯(以下、選択メニュー)を出す。ボタンはアイコンと短い文言で、「コピー」「位置つき」の順に並ぶ。`MATHENAGA_REPO_URL` を渡したビルドでは、区切りの線をはさんで「起票」「編集」が続く(上の「選んだ文章からの起票と原稿の表示」)。ここでいう本文は、各駅(駅の見出しを含む)と、「この章のゴール」「出発点」「ふりかえり」「確認問題」「参考文献」の5つの節である。以下、駅とこの5つの節をまとめて区画と呼ぶ。選んだ範囲が区画の段落に1つもかからないとき(上端のバー、現在地、路線図、この先、札だけを選んだときなど)は出さない。
- 選択メニューは、幅 400px の画面でも1行に収める。「コピーしました」などの知らせを出している間は、2行になってもよい。
- 各ボタンに重ねるかフォーカスすると、選択メニューのすぐ下に次の文を出す。読み上げも同じ文にする。どの文も、ボタンに見えている文言を含む。

| ボタン | 重ねると出す文 |
|---|---|
| コピー | そのままコピー |
| 位置つき | 位置つきでコピー(1行目に位置情報を付ける) |
| 起票 | この記述についてGitHub Issueに起票する |
| 編集 | この段落の原稿をGitHubで開いて編集する |

- 「コピー」は、選んだ文をクリップボードにコピーする。「位置つき」は、1行目に位置 `[章番号:駅番号:段落:文字]`、2行目から選んだ文を書いてコピーする(例: `[3:A04:18:30]`)。
  - 章番号:章の番号。
  - 駅番号:駅の表示番号。駅の外の節では、節の名前(「この章のゴール」「出発点」「ふりかえり」「確認問題」「参考文献」)を書く。
  - 段落:区画の中で、原稿に書いた順に 1 から数えた番号。段落・小見出し・表・別行立ての数式・コードブロックを1つずつ数え、箇条書きは項目ごとに数える(項目の中に段落が2つ以上あれば、段落ごとに数える)。折りたたんだ中身とほかの分野の版も数えるので、開閉や分野の選択で番号は変わらない。駅の見出しと節の見出しは 0 とする。札(「定義 · …」など)は数えない。注の一覧の項目は、区画のほかのすべての段落の後に、注番号の順に1つずつ数える(見出し「注」は数えない)。参考文献の節では、項目を1つずつ数える。番号はビルドで振る。
  - 文字:選んだ範囲の始まりが、その段落の何文字目か(1 から)。段落の外(札など)から選び始めたときは、範囲にかかる最初の段落の 1 文字目とする。
- 選んだ文は、「コピー」でも「位置つき」でも次の形にする。文字は、この形で Unicode の文字を1つずつ数える。
  - 数式は TeX に戻す。行内の数式は `$…$`、別行立ての数式は `$$…$$` にする。数式の途中から選んだり、途中まで選んだりしても、その数式全体を含める。式番号は含めない。
  - 段落の区切りは改行、表のセルの区切りはタブにする。
  - コードブロックの中の空白と改行は、字下げと空行も含めて、そのまま残す。文字の位置も、字下げを数える。
  - 閉じている折りたたみの中身と、隠れている要素は含めない。
  - 注の印(本文の上付きの「注N」)は含めず、文字の位置にも数えない。注の一覧の項目の戻るリンク「↩」も含めない。注の一覧の項目の先頭の「注N」と、参考文献の項目の先頭の「[N]」は、項目の文字として含めて数える。本文の文献の印は、表示の文字「[N]」のまま含める。
- コピーできたら、ボタンの横に「コピーしました」と出し、少し待ってから選択メニューを閉じる。コピーできなければ「コピーできませんでした」と出す。
- Esc、選択の解除、選択メニューの外を押す、のどれかで閉じる。選択メニューが出ている間に Tab を押すと、「コピー」にフォーカスが移る。

**表示の設定**:

- どのページも、画面の右下に設定のボタン(歯車のアイコン)を出す。スクロールしても同じ位置にとどまる。読み上げる名前は「表示の設定」。スクリプトが動かないときは出さない。
- ボタンを押すと、ボタンの上に設定のメニューを開き、最初の項目(テーマ)の選んでいる選択肢にフォーカスを移す。ボタンをもう一度押す、Esc、メニューとボタンの外を押す、のどれかで閉じる。Esc で閉じたときは、ボタンにフォーカスを戻す。メニューが画面に収まらないときは、メニューの中だけを縦にスクロールする。
- メニューの項目は次のとおり(太字が初期値)。選ぶと、ページを読み込み直さずにすぐ反映し、保存する。

| 項目 | 選択肢 | 効果 |
|---|---|---|
| テーマ | ライト / ダーク / **OS に合わせる** | 全ページの配色。「OS に合わせる」では OS の設定(`prefers-color-scheme`)に従う。図の SVG の中の配色も、ページの配色に合わせる(下の Failure modes) |
| 文字の大きさ | 小 / **中** / 大 | 本文の段の文字と用語ポップアップの文字を、本文の地の文が 14px / 16px / 18px になる比で拡大・縮小する。上端のバー、路線図(凡例とボタンを含む)、設定のボタンとメニュー、選択メニュー、起票のアイコンの文字は変えない |
| 本文の幅 | 狭い / **標準** / 広い | 段の幅(上端のバーの中身・本文・路線図の枠をそろえる幅。Performance / Safety の「段の幅」)を 860px / 1160px / 1400px にする。画面がそれより狭いときは画面の幅に合わせる |
| 最初から開く | 証明の詳細 / 確認問題の答え / ほかの分野の版(それぞれ入れる・入れない。初期値はどれも入れない) | 入れたものは、章ページを開いたときと分野を切り替えたときに開いて表示する。設定を変えたときは、開いているページの該当する折りたたみをすべて、その設定の状態にする |
| 用語ポップアップ | **重ねたら出す** / 押したときだけ出す | 「押したときだけ出す」では、用語にポインターを重ねる・フォーカスするだけでは出さず、用語を押す(Enter・Space を含む)と出す。ポインターが用語とポップアップから離れても閉じない。閉じ方はほかは同じ(Esc、外を押す、用語をもう一度押す)。注と文献のポップアップ(P-11)も、この設定に従う |

- メニューの下に「元に戻す」と「しおりを消す」のボタンを置く。「元に戻す」は、上の項目と路線図の倍率を初期値に戻す。「しおりを消す」は、しおり(P-10)をすべて外す。選んだ分野は、どちらでも変えない。
- テーマ・文字の大きさ・本文の幅は、ページを描く前に反映し、開いたときに初期値の表示が一瞬見えないようにする。

**しおり**:

- 章ページの各駅に、しおりのアイコン(しおりの形)を出す。置き場所は起票のアイコンと同じ(上の「改善案の起票」)で、しおりのアイコンを左、起票のアイコンを右に横に並べる。`MATHENAGA_REPO_URL` を渡さずに起票のアイコンがないときも、しおりのアイコンは出す。
- しおりのアイコンの見え方は起票のアイコンと同じ(駅の中にポインターかフォーカスがある間だけ見え、ホバーのできない画面では常に薄く見える)。しおりに入れた駅のアイコンは、塗りつぶした形で常に見せる。
- しおりのアイコンを押すと、その駅をしおりに入れる。しおりに入れた駅のアイコンをもう一度押すと、しおりから外す。アイコンに重ねるかフォーカスすると、入れていない駅では「この駅をしおりに入れる」、入れた駅では「しおりから外す」と出る。読み上げも同じ文にする。
- どのページも、上端のバーにしおりのボタン(アイコンと「しおり」)を出す。章ページでは分野の切り替えのすぐ右、トップページと分野の入口ページではサイト名のすぐ右に置く。押すと、ボタンの下にしおりの一覧を開き、最初のリンクにフォーカスを移す。
  - 一覧は、しおりに入れた駅を読む順に並べ、各行に「第N章 〈表示番号〉 〈駅名〉」(その駅へのリンク)と、しおりから外すボタン(×)を置く。しおりが1つもなければ「しおりはまだありません。駅のしおりのアイコンを押すと、ここに加わります。」と出す。
  - リンクを押す、ボタンをもう一度押す、Esc、一覧とボタンの外を押す、のどれかで閉じる。Esc で閉じたときはボタンにフォーカスを戻す。
- しおりは駅の ID で覚えるので、駅の表示番号や章番号が変わっても同じ駅を指す。原稿から消えた駅は一覧に出さない。ほかのタブで入れたり外したりしたときは、開いているページの表示も合わせる。
- スクリプトが動かないときは、しおりのアイコンもボタンも出さない。

**ブラウザに保存するもの**:

| キー | 中身 |
|---|---|
| `mathenaga-field` | 選んだ分野(上の「分野の切り替えと表示規則」) |
| `mathenaga-settings` | 表示の設定。項目ごとの値を1つの JSON にする |
| `mathenaga-map-zoom` | 路線図の倍率([route-map.md](route-map.md)) |
| `mathenaga-bookmarks` | しおりに入れた駅の ID の並び。1つの JSON の配列にする。配列でない値は、しおりがないものとして扱う |

- GitHub Pages ではほかのサイトと同じオリジンになることがあるので、キーはすべて `mathenaga-` で始める。
- 保存した値が読めない、または項目の値が選択肢にないときは、その項目を初期値として扱う。ほかの項目の値は使う。

## Failure modes

| きっかけ | 外から見える振る舞い | 回復 |
|---|---|---|
| `defs.json` を取得できない(通信の失敗など) | ポップアップに「定義を読み込めませんでした」と出る。本文は読める | 次にポップアップを開くときに取得し直す |
| `defs.json` に定義がない(ビルドの不具合) | ポップアップに「定義が索引にありません」と出る | ビルドの不具合として直す。同じビルドの出力なら起きない |
| `?field=` が分野の ID でない | 指定がないものとして、前回の値か未選択で表示する | なし |
| アンカーが壊れている(`#%` のように、URL の `%` の書き方が正しくない) | アンカーがないものとして表示する。分野の切り替え、ポップアップ、表示の設定、しおりは動く | なし |
| `localStorage` が使えない(プライベートモードなど) | 分野の切り替え、表示の設定、路線図の倍率は、そのページの中だけで効く。しおりはそのページの中だけで効き、ほかのページの一覧には出ない | なし |
| 保存した設定の値が壊れている(手で書き換えた、古い形など) | 読めない項目は初期値で表示する。設定のメニューで選び直すと、正しい値で保存し直す | なし |
| 図の SVG を `<img>` で表示するブラウザが、ページの配色(`color-scheme`)を SVG の中の `prefers-color-scheme` に渡さない(忘れやすい) | テーマを OS と違う配色に固定したとき、図だけが OS の配色になる。Chromium は渡すことを確かめた | なし |
| Google Fonts を読み込めない(通信の失敗、遮断など) | システムの書体で表示する。レイアウトは崩れず、本文と数式は読める | なし |
| スクリプトが動かない | 未選択の表示になる。折りたたみは HTML の機能なので動く。ポップアップと現在地バーの強調は動かない。注の印と文献の印は、注の一覧と参考文献の項目へのリンクとして動く。本文を選んでも選択メニューは出ず、ブラウザのコピーだけが使える | なし |
| クリップボードに書けない(権限がない、古いブラウザなど) | 選択メニューのボタンの横に「コピーできませんでした」と出る。選択は残るので、ブラウザのコピーは使える | なし |
| 今の章が選んだ分野の図に載らない(忘れやすい) | 帯のない図と「この章は〈分野名〉の路線図に載っていません」が出る | なし |
| 幅の狭い画面で長い数式・表・コードがはみ出す(忘れやすい) | その要素の中だけで横にスクロールする。式番号は見えたまま | なし |

## Performance / Safety

| 項目 | 要件 |
|---|---|
| 配信 | 静的ファイルのみ。閲覧時に読みに行くデータは同じサイトの `defs.json` だけ(ページが読み込む CSS・スクリプト・フォント・図を除く)。サイトの外から読み込むのは、Google Fonts の CSS と書体だけ |
| 閲覧環境 | PC とスマートフォン(幅 400px 程度)。ページ全体の横スクロールは出さない。横スクロールしてよいのは、路線図・表・別行立ての数式・コードブロックの内側だけ |
